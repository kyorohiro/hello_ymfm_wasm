# CD-DA PCM render core

This original Tetorica implementation is distributed under the included
BSD-3-Clause license. It does not incorporate another emulator's CD controller
or audio renderer. It follows the existing `native/audio_effect/sample.c`
approach of interpolating only the samples needed by the output callback.

The input is immutable, interleaved, little-endian stereo PCM16 at 44,100 Hz.
WAV parsing, track manifests, storage ownership, scheduling and mixing belong
to the host. The core is independent of HuC6280, MSM5205 and machine emulation.

`cdda_pcm.h` exposes a C ABI and a plain state structure. Compile `cdda_pcm.c`
as C11 or C++14. Attach borrowed bytes with `cdda_pcm_prepare`; retain their
lifetime until the next source replacement or state destruction. Rendering
replaces planar Float32 output buffers, including silence, and never allocates,
locks, reads files or calls the host. An invalid operation preserves state.

The source cursor uses integer frames plus a rational phase with denominator
`output_rate`. Linear interpolation preserves separate left/right channels;
the final source frame is held until its duration expires. At EOF the cursor
is exactly the source frame count. Output block partitioning does not alter
the PCM or cursor. `output_frames` also counts silent ready/paused/ended output,
so hosts can schedule source controls against the same audio clock as PSG/ADPCM.

States are `ready`, `playing`, `paused`, and `ended`. `play` starts from frame
zero. `resume` continues a paused cursor. `stop` retains the source and returns
to ready/frame zero. Seeking preserves playing/paused state; seeking exactly
to EOF ends playback. Seeking backwards from ended returns to ready. Gain and
mute preserve cursor progression and are retained on source replacement.

Browser hosts use `cdda_pcm_prepare_windowed` and `cdda_pcm_set_window` to
refresh a borrowed PCM16 scratch region without resetting phase or position.
`web/cdda_pcm.js` retains the complete source bytes in JS and uses a fixed
4 KiB WASM input window and two fixed 128-frame output buffers. It copies only
the upcoming PCM16 bytes, uses no full-track Float32 decoding, allocates no
temporary views during rendering and never grows WASM memory. Source bytes
must not be mutated or detached while attached. Preparation is atomic after
validation. The 256 MiB limit applies to PCM bytes, not decoded Float32 data.

The WASM module has fixed 128 KiB memory and no host imports. It is generated by:

```sh
sh scripts/build_cdda_wasm.sh
node scripts/check_cdda_core.mjs
```

The check compiles the actual source as C11 and C++14, compares full/borrowed
window Native output to the actual WASM and an independent per-frame reference,
checks 8/44.1/48/384 kHz output, lifecycle/EOF/mute/gain/error behavior and
arbitrary block partitions. Audio fixtures are generated arithmetic PCM owned
by the test; no third-party recordings are needed.

This is a playback source, not a sound-chip emulator. It does not implement
physical CD access, CUE/BIN, CD sectors, compressed codecs, pre-emphasis,
controller registers or machine-specific CD commands.
