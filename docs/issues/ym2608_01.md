# YM2608 未対応機能の整理

調査日: 2026-09-07

このリポジトリのソースコードを確認した時点の状況。
ymfm コアに機能があっても、WASM・JavaScript・Playground 側の接続が
未実装のものがある。SSG 出力・ADPCM-B 接続は同日実装し、生成済み WASM の
PCM テストで確認済み。実機との比較や実曲の聴取確認は未実施。

## 対応済み

- FM 6ch、2 port、パン、LFO。
- レジスタ直接操作と FM 用の `YM2608Synth` / `YM2608RuntimeSynth`。
- ステータス読み取り、IRQ 状態取得、読み書き・IRQ のフック。
  ただし、タイマー由来の IRQ 動作には後述の未対応部分がある。
- リズム用 ADPCM-A ROM の低レベル読み込み API `loadAdpcmARom()`。
- SSG の左右への音声ミックス。
- ADPCM-B のメモリ読み書き、`loadAdpcmBMemory()` / `clearAdpcmBMemory()`。
- VGM の `0x67` / type `0x81` データを ADPCM-B メモリへ転送して再生。

## 未対応・部分対応

### SSG 3ch

- ymfm コアには SSG とリサンプリング処理がある。
- WASM の `ym2608_generate()` で SSG の `output.data[2]` を左右へ加算するよう修正済み。
  同梱の `examples/vgmrender/vgmrender.cpp` と同じ加算方法を使い、ミックス後にクリップする。
- 高レベル Synth API は FM 専用で、SSG のトーン・ノイズ・エンベロープ操作 API は未対応。

### リズム音源（ADPCM-A）

- コアのリズム生成、WASM の ROM 保持・読み出し、左右の音声へのミックスは実装済み。
- `Ym2608` と `Ym2608AudioEngine` には `loadAdpcmARom()` がある。
- Playground 用の `ym2608-worklet.js` には ROM を受け取って読み込む処理がない。
- リズム用の高レベル操作 API も未対応。
- したがって全面的な未実装ではなく、低レベル対応済み・Playground への接続不足。

### ADPCM-B（サンプル再生・録音）

- WASM に 2 MiB のメモリを追加し、`ACCESS_ADPCM_B` の読み書きを接続済み。
- VGM の type `0x81` ブロックからメモリサイズ・開始位置・サンプルを取り出し、
  後続のレジスタ書き込み前に転送する。分割ブロックは指定位置へ追記する。
- Player の新規ファイル読み込み、音声エンジンの reset 時にメモリをクリアする。
  チップ単体の reset はメモリを保持し、VGM のループ位置へ戻る場合も保持する。
- 不正な範囲・2 MiB 超のメモリ指定はエラー。2 台目の YM2608 用データは警告してスキップする。
- Playground 用のサンプル受け渡し、再生・録音の高レベル API は未対応。
  CPU 経由のメモリ書き込みへの対応は、音声入力からの録音機能への対応を意味しない。

### Timer A/B・タイマー IRQ・CSM

- WASM 側で `ymfm_set_timer()` を実装しておらず、タイマー満了を
  `engine_timer_expired()` に通知する処理がない。
- そのため Timer A/B の時間経過、タイマー由来のステータス更新・IRQ、
  Timer A 満了に依存する CSM の自動キーオンは未対応。
- `readStatus()` / `readStatusHi()` / `getIrq()` が存在するだけでは、
  タイマー動作への対応を意味しない。

### BUSY・外部 I/O

- `ymfm_set_busy_end()` / `ymfm_is_busy()` はデフォルト実装のままで、BUSY は常に false。
- 外部 I/O の読み出しは `0`、書き込みは無処理。ホスト側への接続がない。

## VGM Player と Playground の違い

VGM Player（`docs/vgm_analyzer/`）には、Playground の FM 専用 Synth とは
別の再生経路がある。リズム音源は Player 側まで接続済み。

```text
VGM の YM2608 書き込み（0x56 / 0x57）
  → VgmPlayer
  → Ym2608AudioEngine.writeYm2608()
  → Ym2608 / YM2608 WASM
```

- VGM Player は FM 専用フィルターを通さず、YM2608 のレジスタ書き込みを渡す。
- Player 画面には `ym2608_adpcm_rom.bin` などを選択する ROM 入力がある。
  選択した ROM はエンジン作成時、または既存の YM2608 エンジンに
  `loadAdpcmARom()` で渡される。
- 通常の VGM の書き込み間隔は VGM の wait に従って進むため、
  Timer A/B のホスト実装がないこと自体で通常の FM・リズム再生が止まるわけではない。
  チップ内部のタイマーに依存する CSM などの制限は残る。

| 機能 | VGM Player | Playground の高レベル Synth |
| --- | --- | --- |
| FM | 対応 | 対応 |
| リズム（ADPCM-A） | ROM を選択すれば再生経路あり | ROM 受け渡し・専用 API が未対応 |
| SSG | 音声出力対応済み | raw write で発音可能、専用 API は未対応 |
| ADPCM-B | VGM 内のサンプルデータ読み込み・再生に対応 | サンプル受け渡し・専用 API が未対応 |

## 検証

- `docs/playground/ym2608_audio.test.mjs` で配布用 WASM を実行し、SSG の左右出力・ミュート、
  VGM 経由の ADPCM-B 発音・パン・分割ブロック・再スタート・曲切り替え時のメモリクリア、
  CPU メモリ書き込みと読み戻し、不正ブロック・2 台目データの扱いを確認。
- Node.js の隔離 VM を shell 環境として使う。生成 JS の ES module 構文のみを読み替え、
  WASM バイナリは `docs/generated/ym2608_wasm.wasm` をそのまま実行する。
- チップ reset は内部リサンプラーの位相を保持するため、再スタート時の境界サンプルには
  差があり得る。発音レベル・パン・発音長を検証する。
