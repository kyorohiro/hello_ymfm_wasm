# VGM 自動テストの不足項目

## 位置づけ

[自動テスト方針](vgm_autotest_01.md) に対し、今後追加するケースを整理する。
この文書はテスト追加の作業一覧であり、以下の仕様対応や検証が完了したことを意味しない。

対象は主に `vgm-parser-mock.test.mjs` と `vgm-player-mock.test.mjs`。
既存の音源別テストに部分的な検証がある場合も、Player → Mock の経路で不足しているものを含む。
YM2612 DAC の仕様修正は [dac_01.md](dac_01.md) と対応づけて進める。

## 現在の到達点と限界

更新: Player の20形式の通常書き込み、メモリ配送、登録先解決、DAC の主要仕様、
再生操作、Analyzer の実シーク関数、警告通知のテストを追加した。
YM2612 DAC の修正前には追加した22テストが失敗し、修正後は成功した。
バンク連結とバンク内ブロック番号、リセット時の状態クリアも修正した。

- Parser の `sample` は VGM 時刻、Player Mock の `frame` は生成済みの出力フレーム数。
- バッファサイズ変更とは別に、Parser の wait 分割も検証している。
- 無音 Mock に加え、左右で符号の異なる連番音声で出力の欠落・重複を検証している。
- メモリテストは呼び出し内容とクリアの検証。実音源内のメモリ内容は音源別テストで扱う。
- シークでは先読みされた命令があるため、シーク中のログと再開後のログを分離して比較する。

## 優先度1：YM2612 DAC の仕様ベースのテスト

以下は Parser と Player の両方で検証する。期待する値列と時刻を仕様から決め、
修正前に失敗することを確認してから実装を直す。既知の誤動作を期待値にしない。

| 状態 | ケース | 確認する結果 |
| --- | --- | --- |
| [x] | `0x91` の `stepBase` とステップ幅 | 識別可能な値を並べたバンクから、指定位置の値だけが順に届く |
| [x] | `0x93` の各長さモード | 命令数・ミリ秒・末尾まで・長さ維持を個別に確認し、回数と停止位置が合う |
| [x] | 開始位置 `0xFFFFFFFF` | 再設定・再開時も仕様に従う位置から値が届く |
| [x] | 逆再生 | 先頭・末尾・1要素の区間で順序と停止位置が合う |
| [x] | `0x95` のバンク内ブロック番号 | 異なるバンクに同じ番号のブロックを置き、指定バンクの値だけが届く |
| [x] | `0x95` のループフラグ | ループ指定の有無で、繰り返しと停止が正しく切り替わる |
| [x] | 初回書き込み | 開始命令と最初の wait の境界で、仕様に従う時刻に1回だけ届く |
| [x] | 周波数変更 | 演奏途中の変更後も周期と位相の扱いが仕様に合う |
| [x] | 停止・全停止・再開 | 停止後に余計な値が届かず、他ストリームは必要に応じて継続する |
| [x] | 予約 ID `0xFF` | 全停止以外の命令で通常のストリームとして作られない |
| [x] | 複数ストリーム | 異なる周期・送り先で状態が混ざらず、同時刻の処理順が確認できる |
| [x] | 直接書き込みとの比較 | 同じ演奏を通常命令とストリームで表し、双方が明示した期待ログに一致する |

空バンク、範囲外の開始位置、0件の長さ、0 Hz、ステップ幅0なども追加する。
これらの期待結果は、仕様に定義があるかを先に確認する。未定義の場合は、
アプリとして採用する警告・無効化などの方針を記載してからテストする。

## 優先度2：Player の配送経路とメモリ

- [x] Parser で検証済みの通常書き込み20形式を、Player 経由でも確認する。
      OPM・OPN・OPNA・OPNB・OPL・OPL3・OPL4・RF5C164 などのアダプターを対象にする。
- [x] PSG の値を Player 経由で確認する。Mock にメソッドが存在するだけでは検証済みとしない。
- [x] `getVgmTarget(type, index)` を提供する Mock で、複数チップ登録経路を確認する。
      従来メソッドへの誤った代替呼び出しも検出する。
- [x] Y8950・YMF278B・OPNA・OPNB・RF5C164 のメモリ操作を、対応する Player 経路で確認する。
      データ、送り先、オフセット、サイズ、ロードとレジスタ書き込みの順序を比較する。
- [x] 曲の切り替え時に必要なメモリクリアが呼ばれ、前の曲のデータが残らないことを確認する。
- [x] リセット時に必要なメモリが再ロードされ、同じ配送ログが再現することを確認する。
- [x] 未登録のインスタンスを第1チップへ配送しないことを Mock で確認する。
- [ ] DAC のインスタンス対応を実装する際、通常命令と wait 中の書き込みが同じ登録先へ届くことを確認する。

同一チップ2基の実音源による再生検証は今回の対象外。Mock による登録先の区別は、
実音源での2基構成の動作保証とは分けて記録する。

## 優先度3：時刻・再生操作・シーク

- [x] ストリーム周期の直前・一致・直後で `consumeWait()` を分割し、書き込みの欠落・重複がないことを確認する。
- [ ] 非整数周期のストリームを長めに流し、累積誤差と最終的な書き込み数を確認する。
- [x] 44,100 Hz 未満の出力も使い、出力0フレームになる短い wait の後も端数が保持されることを確認する。
- [ ] 出力フレームが同じ位置に丸められる複数の命令について、配送順が保たれることを確認する。
- [x] DAC が動作中の pause/resume、stop/play、reset を確認する。通常書き込みだけのケースと区別する。
- [x] ループ位置あり・なしの両方で、DAC の値列・周期・バンク状態を確認する。
      通常の Player ループには既存テストがあるため、ストリーム固有の状態を追加対象にする。
- [x] Analyzer の実際のシーク経路をテストへ接続する。Player にシーク API があると仮定して別実装しない。
- [ ] ストリームの途中、開始・停止境界、メモリロード後へシークし、通常再生の同区間と比較する。
      シークのために先頭から再実行したログは、到達後のログと分ける。

## 優先度4：不正入力・警告・出力の保全

- [x] DAC 命令とデータブロックを各バイト位置で切断し、不完全な書き込みやメモリロードが届かないことを確認する。
- [ ] 不正なブロックサイズ・オフセットなどで、無限ループや無制限の処理にならないことを確認する。
- [x] 未対応ストリームと対応済みストリームを同時に動かし、対応済みの演奏が維持されることを確認する。
      未対応ストリーム単独の警告・再有効化防止は既存テストがある。
- [x] 曲の切り替え後に前の曲のストリーム状態が残らないことを Player 経由で確認する。
- [x] 無音 Mock に加え、連番など識別可能な音声を返す Mock で、バッファ境界の欠落・重複・左右の取り違えを確認する。
      既存 `vgmplayer.test.mjs` のキュー・pause・loop テストを活用し、未検証の条件を追加する。
- [x] UI の警告表示・消去を実際の Player の警告通知に接続して確認する。
      警告欄単体のテストと、Player から画面までの接続テストを区別する。

未完了のチェックは継続課題として残す。特に、DAC のインスタンス配送は今回拡張していない。
長時間の非整数周期、複合メモリ状態でのシーク、不正入力の資源使用上限などは追加検証が必要。
UI 通知は実 Player と画面の警告関数を VM で接続した確認であり、ブラウザー操作の E2E ではない。

仕様の根拠は [VGM 1.71](https://github.com/vgmrips/vgmplay-legacy/blob/master/VGMPlay/vgmspec171.txt)。
初回書き込みは [libvgm の daccontrol_start](https://github.com/ValleyBell/libvgm/blob/master/emu/dac_control.c) の
次回更新に初回を含める処理も参照した。ミリ秒モードは仕様上の時間の意味に従い
`floor(frequency * milliseconds / 1000)` とした。参照コードの逆の式は採用していない。
空データ・範囲外は配送せず、ステップ幅0は1として扱う。要求長がデータを超える場合は
利用可能なデータまでで停止する実装方針とし、すべての参照プレイヤーとの一致は保証しない。
