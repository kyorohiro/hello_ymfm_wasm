# RF5C164 を Playground から操作する構想

## 目的・範囲

Genesis の YM2612 / Sega PSG / DAC に加えて、Mega-CD の PCM 音源
RF5C164 を Playground のコードから操作できるようにする。
RF5C164 は ADPCM ではなく、波形 RAM を読む8 CHの PCM 音源。

今回の `sample` API は汎用 PCM プレイヤーであり、RF5C164 のレジスタや
波形 RAM、ループマーカーの動作を再現する API とは別物。
CD-DA 相当の長い音声を鳴らす用途は既存の `stream` に任せる。
ディスクドライブや Mega-CD 全体のエミュレーションは対象外。

基本 API と Playground 接続を実装済み。ブラウザーでの試聴と実曲の検証は未確認。

## 既存の土台

`web/rf5c164.js` の `Rf5c164` に以下の機能がある。

- WASM の初期化、reset、dispose。
- `writeRegister(register, value)` による直接操作。
- `loadMemory(bytes, offset)` による絶対アドレスへの RAM 転送。
- `writeMemory(offset, value)` による選択中の4 KiBウィンドウへの書き込み。
- `loadBankedMemory(bytes, offset)` による VGM 用のバンク相対転送。
- `generateStereo(frames)` による PCM 生成。

コアは `third_party/mame-rf5c164/`、WASM 境界は `wasm/rf5c164_wasm.cpp`。
既存の Analyzer / 音声テストは再利用するが、Playground の操作・接続の検証は別途必要。

## Playground API 案

波形を RAM に配置し、物理 CH を指定して発音する。
数値 CH は 0..7、定数表記は CH1..CH8。自動の声割り当ては初期対象外。

```javascript
// Playground API
const pcm = await createSoundChip("rf5c164");

// RF5C164 用に変換した波形。WAV ファイルそのものではない。
await pcm.loadMemory(sampleBytes, 0x0000);

pcm.setChannel(CH1, {
  start: 0x0000,
  loopStart: 0x0000,
  step: 0x0800,
  volume: 200,
  pan: { left: 15, right: 15 },
});

pcm.keyOn(CH1);
await beat(1);
pcm.keyOff(CH1);
```

| API 案 | 役割 |
| --- | --- |
| `loadSample(source, options)` | WAV / FLAC をデコードし、チップ用波形へ変換・配置する |
| `loadMemory(bytes, address)` | RF5C164 用の生バイトを波形 RAM へ転送。完了後に発音できるようにする |
| `setChannel(ch, options)` | 開始位置・ループ位置・step・音量・左右音量を設定 |
| `setPitch(ch, step)` | 再生中のピッチを変更。音名ではなく生の step 値 |
| `keyOn(ch)` / `keyOff(ch)` | 物理 CH の発音・停止 |
| `writeRegister(register, value)` | 低レベルの直接操作 |
| `reset()` / `dispose()` | 状態初期化・リソース解放 |

`setChannel` の省略項目は現在値を維持する。
高レベル操作では CH 選択・チップ全体の有効化・CH on/off のビット管理を内部で行う。
`keyOn` は再トリガーする。`reset` はレジスタを初期化し RAM を保持する。
`dispose` と Playground の Stop は追加したチップを破棄する。操作は Promise を返すため、順序が必要な箇所では await する。
直接レジスタ操作とヘルパーを混ぜた場合も、選択 CH・制御状態を食い違わせない。

## 入力形式と Analyzer からの受け渡し

対象は **WAV / FLAC / BIN ファイルと、バイナリ配列**。
バイナリ配列は `Uint8Array` / `ArrayBuffer` を受け取る設計とする。
JSON の付随ファイルは使わず、配置アドレス、ループ位置、再生 step、音量などは
JavaScript の API で指定する。

| 入力の内容 | 扱い |
| --- | --- |
| WAV / FLAC | デコードした PCM を RF5C164 用の波形形式に変換して配置する |
| BIN | RF5C164 用に変換済みの生バイトとして、そのまま配置する |
| `Uint8Array` / `ArrayBuffer` | 入れ物の型。内容が WAV / FLAC か生バイトかを呼び出す API で区別する |

```javascript
// Playground API。ファイルを読み込んだ後のバイト列を渡す例。
await pcm.loadSample(wavBytes);    // WAV / FLAC のデコード・変換・配置
await pcm.loadMemory(chipBytes, 0x0000); // BIN の内容、または自作の生バイト列
```

`loadSample` はローカル URL・Blob/File・Uint8Array・ArrayBuffer を受け取る。
FILES はバイト列を読み出して渡す。BIN は読み出した生バイト列を `loadMemory` に渡す。
`loadSample(source, {address: 0, loopStart})` の loopStart はサンプル先頭からのオフセット。
省略時は末尾から無音領域へループする。返り値 `{start, loopStart, step}` を setChannel に渡せる。
ステレオは平均してモノラル化する。自動 RAM 配置・リサンプリングは行わず、
マーカーと無音領域を含めて64 KiBを超える場合はエラーにする。
FLAC は利用するデコーダーでの対応を確認し、非対応時は明示的にエラーにする。
生バイトを WAV / FLAC としてデコードしたり、音声ファイルのヘッダーを
そのまま波形 RAM へ転送したりしない。

VGM Analyzer からは、WAV ならデコード・再変換、RF5C164 の生データなら
BIN またはバイナリ配列で変換せず受け渡す方針。
Analyzer の `rf5c164_samples.js` は完全な波形を64 KiBの RAM スナップショットとして保持する。
ダウンロードしたデータとの実曲による往復確認は未実施。RAM を途中で書き換える曲では、
どの時点のデータを取り出したかと、再生に必要なアドレス・ループ設定を確認する。

## チップ固有の制約

既存コアの動作に合わせて扱う。

- RAM は64 KiB。転送先の範囲外アクセスや意図しない重複を確認できるようにする。
- 開始アドレスは256 byte単位。`start` はバイトアドレスで受け、
  非整列値はエラーにする。
- ループアドレスは16 bitのバイトアドレス。
- `step` は16 bitの進み幅。`0x0800` はコアの内部更新1回につき1 byte進む値であり、
  WAV のサンプルレートや固定の音名を直接意味しない。
- 音量は0..255、左右音量はそれぞれ0..15。
- 波形形式はチップ固有の符号・振幅表現。`0xff` はループマーカーとして扱われる。
  一般的な unsigned / signed 8 bit PCM をそのままコピーする前提にしない。
- ワンショットは、末尾から無音領域へループさせる等の扱いを検証する。
  通常の `sample.play` のような自動終了を当然とはしない。

手作りの短い波形で自動テスト済み。WAV / FLAC の変換とマーカー生成も実装した。
RAM の自動配置と容量に合わせたリサンプリングは未実装。

## 音声接続・スレッドの役割

- main thread：AudioContext / Worklet の初期化、UI、必要なファイル読み込み。
- Worker：CH設定からレジスタ列を作り、波形転送・発音・停止を直接送る。
- AudioWorklet：RF5C164 の WASM を動かして PCM を生成する。
- 出力：既存のマスター native FX に接続し、他音源と混合する。

発音のたびに Worker → main → Worklet と往復しない構成を維持する。
転送完了やエラーも専用ポートで返す。表示・記録用の observer は別途維持する。

初期化ヘルパーの返り値は、オフライン用の生の `Rf5c164` インスタンスと区別する。
Playground は再生・Stop・後始末まで管理する操作用オブジェクトを返す案。
不要なチップの WASM を初期化しないようにし、単独埋め込みの構成も維持する。

## 後段で検討するもの

- 元音程を登録したサンプルに対する `noteOn("C4")` 相当のヘルパー。
  再生stepだけでは元波形の音名が分からないため、基準音・基準step等が必要。
- MIDI接続、声割り当て、複数チップ、音源間の厳密な時刻同期。

まず物理CH・RAM・レジスタを意識した操作を完成させ、音名指定やMIDIは別段階とする。

## 実装と確認方法

- サンプル：`docs/playground/examples/pcm/rf5c164-sine.js`。Worker on/off 両方で試聴する。
- 制御：`web/playground_rf5c164.js`、音声接続：`web/playground_rf5c164_audio.js`、生成：`web/rf5c164-worklet.js`。
- 自動テスト：`node --test web/playground_rf5c164.test.mjs`（実WASM・直接ポート・Worklet）。
- WAV / FLAC の実ファイル読み込み、連続Run/Stop、他音源との混合・FX、Windows試聴は手動確認が残る。
