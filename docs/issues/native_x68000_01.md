# X68000（YM2151＋OKIM6258）のNative対応

2026-10-22。既存X68000 modeをTauriのNative音声へ接続する。Web Audioを既定にする方針は維持する。

## 対応範囲

- Browser/WASMと同じymfm YM2151とMAME由来OKIM6258コアを直接C++で生成する。FMは8CH、ADPCMは1ストリーム。
- X68000の既定clockはYM2151が4 MHz、OKIM6258が8 MHz。OKIの512／768／1024分周・左右出力設定を保持する。
- 公開APIは既存の`opm`／`adpcm`、`useSoundChip('ym2151')`／`useSoundChip('okim6258')`。OPMの公開オペレーター順は既存のM1／C1／M2／C2のままにする。
- Main／Workerから同じNative音源へ時刻付き命令を送り、演奏owner取消しと古いsessionを区別する。追加のYM2612／Sega PSGは生成しない。
- KeyboardのChip／CH指定、YM2151のOperators・LFO・noise編集と試奏、OKIのサンプル選択・波形確認・試奏を既存UIへ接続する。
- OKIサンプルは既存の符号化器で変換し、64 KiB単位で準備してcommitする。転送中の取消しでは以前のサンプルを保持する。音声callback内ではメモリーの確保・解放を行わない。
- サンプルは生成時に用意した16 MiBの二重バンクで交換する。commitの適用を確認して読込み完了を返す。演奏コードから手動試奏への割込みは拒否し、画面で明示的に読込み直す場合は試奏を解放して交換する。
- Stopは発音と予約を止め、FM音色・KC/KF・LFO設定・clock・OKIサンプル・pan／dividerを保持する。
- YM2151の試奏は通常の生成間隔でKey Offを反映してからKey Onする。制御処理の中でPCMを生成・破棄しない。LFO・noise・タイマー／CSMも試奏保護の対象にする。
- 両チップをそれぞれミキサーへ登録し、共通FX／liveFx・Audio monitor・最終出力録音へ接続する。表示のために再生PCMをWebViewへ転送しない。
- Native状態の取得は非同期で、適用済み状態を観察する。C++コア内部のread／PCM生成は同期のままにする。

## 検証方針

- 実際に配布しているWASMとNativeのPCMを44.1／48／96 kHzで比較する。FM全CH・operator順・LFO／noise・pan、OKI分周・raw nibble・sample repeat／終端・clock変更・Stopを含む。
- Rustで転送境界・commit・owner取消し・manual lease・共有レジスター保護・共通ミックス／FX／録音を確認する。
- JSで既存Main／Worker APIとのレジスター列一致、実MessagePort、非同期ロード中の取消し、適用済み状態と先読み状態の分離を確認する。
- Chromium／WebKitで初期コード、Main／Worker、両チップのKeyboard／Operators、OKIサンプル読込み、Stop／mode切替を確認する。Native IPCは模擬し、実音声デバイスは開かない。

## ソースと配布

`src-tauri/native-x68000/`に原典・ハッシュ・ライセンスを保存し、共有ymfmは`native-genesis`から一度だけコンパイルする。X68000のラッパー・OPM・OKIライブラリーはGNUリンカー向けに共有providerより前へ配置する。

OKIはPlaygroundと同じ4-bit ADPCM／12-bit出力（flags 12）で生成する。Native向けの生成ソースでは、共有デコードテーブルの初期化をC++のスレッドセーフな一度だけの初期化に変更し、別音源の作成と再生中のcallbackの競合を避ける。デコード処理は変更していない。生成した変更も`sync_native_x68000.py --check`で検査する。

既存ymfmのBSD通知に加え、OKIM6258のBSD通知をTauriのresourceへ同梱する。

## 2026-10-22の結果

- JavaScript全体: 3,308件成功、失敗・skipなし。新しいendpoint・Main接続・実MessagePort経由のWorker・owner取消し中の転送停止・UIによる明示置換を含む。
- Rust全体: 212件成功、失敗なし、既存の実音声デバイス等の4件はignored。最後のタイマー／CSM保護の修正後も、X68000専用16件が成功。チップ別の未来命令取消し、共有レジスター保護、サンプル交換、実PCMの独立ミキサー／FX／録音経路を確認した。
- macOS ARM64で実配布WASMとNativeの独立FM／OKI出力を比較し、44.1／48／96 kHzの42ケース・258,048出力フレームで最大差は0。詳細は[native_x68000_pcm_validation.json](native_x68000_pcm_validation.json)。
- C++ fixtureで16 MiBの転送境界・交換・IRQ／状態取得・Stop／reset・試奏再発音と取消しを確認した。callback内の確保・解放は0。AddressSanitizerの検査も成功した。
- Chromium／WebKitで既存Native経路の回帰確認が成功。最終Tauri配布データでも初期コードのMain／Worker再生、8CHのKeyboard、YM2151のGuitar入力と両チップのPCキー試奏、Operatorsからの音色・分周編集、Cassette内WAVのOKI読込み、波形情報、独立ミキサー、Stop保持、mode切替が成功した。Native IPCは模擬している。
- 原典11ファイルと共有ymfm 5ファイルのハッシュ、Tauriへ取り込んだ829ファイルの整合性を確認。最終配布データを含む`cargo build --offline --locked`も成功した。
