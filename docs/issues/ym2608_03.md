# RF5C164 対応 — Mega-CD の PCM 再生

作成日: 2026-09-08
状態: 対応方針案（未実装）

## 目的と範囲

既存の Mega Drive 再生（YM2612 + Sega PSG）に RF5C164 を追加し、
Mega-CD / Sega CD の VGM に含まれる PCM パートを再生できるようにする。
RF5C164 は独立した音源なので、YM2608 の ADPCM 機能への追加ではなく、
Genesis の音声ミックスへの追加として実装する。

この issue の初期対象は VGM Player / Analyzer。
CD-DA の外部音声トラック再生・同期、ディスクイメージ読み込み、
Mega-CD 本体の CPU / CD ドライブのエミュレーションは別課題。
「Mega-CD の PCM 対応」と「CD の音声を含む完全な再生」を区別する。

## 現状

- `src/`・`wasm/`・`web/` に RF5C164 コア・接続はない。
- `web/genesisaudioengine.js` は YM2612 と Sega PSG を同じ出力レートで合算する。
- `web/ym2612vgm.js` は RF5C164 の書き込みイベントを生成しない。
  `0x68` は内容の記録と警告までで、PCM RAM への転送は行わない。
- 同パーサーのデータバンクは同じ type の追加ブロックで上書きされる。
  RF5C164 のバンク転送対応では、連結とブロック位置の管理が必要。
- `web/vgmplayer.js` のイベント転送に RF5C164 用の経路がない。
- Analyzer の Genesis エンジン生成は現在クロックを渡していない。
  PCM 追加時には、ヘッダーのクロックとエンジン再利用条件も見直す。

## 推奨する構成

```text
VGM parser → VgmPlayer → GenesisAudioEngine
                          ├─ YM2612
                          ├─ Sega PSG
                          └─ RF5C164（使用するファイルで追加）
                               ↓ 共通レートへ変換して左右に合算
                          既存の音声出力
```

- RF5C164 を単独で生成・検証できるコアとし、C++ / WASM / JS の層を用意する。
  既存の Sega PSG の構成を参考にする。
- コア候補は MAME の RF5C164 実装。採用前に固定リビジョン、依存部分、
  著作権表示・BSD-3-Clause の同梱方法を確認し、必要部分を独立化する。
  RF5C68 と完全に同一と仮定せず、RF5C164 の出力仕様を選択する。
- 8ch、64 KiB 波形 RAM、チャンネル選択・RAM バンク選択、音量、左右パン、
  再生ステップ、開始位置、ループ位置、チャンネル On/Off を扱う。
  サンプルの符号形式と `0xFF` ループマーカーも検証する。
- ネイティブ生成レートはクロック / 384 を基準とし、Genesis の出力レートへ
  変換する。小さいバッファでも位相・端数を保持し、長時間のずれを防ぐ。

コア仕様の確認先: [MAME RF5C68 / RF5C164 実装](https://github.com/mamedev/mame/blob/master/src/devices/sound/rf5c68.cpp)。
同実装にもチップ差分の TODO があるため、移植だけで実機一致とは扱わない。

## VGM の対応範囲

| 項目 | 対応内容 |
| --- | --- |
| Header `0x6C` | RF5C164 クロックの読み取り。古い・短いヘッダーは未使用扱い |
| Command `0xB1` | レジスタ書き込み |
| Command `0xC2` | PCM メモリへの1バイト書き込み |
| `0x67` / type `0xC1` | 開始アドレス付き RAM データの転送 |
| `0x67` / type `0x02` | PCM データバンクへの蓄積 |
| `0x68` / type `0x02` | データバンクから PCM RAM へ転送 |

仕様: [VGM Specification](https://vgmrips.net/wiki/VGM_Specification)
（確認に使用した[仕様ミラー](https://vgmrips.theclassicgamer.net/VGM_Specification)）。

- command `0xC2` と data block type `0xC1` の番号を混同しない。
- RAM 直接転送とバンクを介した書き込みを別 API にする。
  各 VGM 命令がどちらを要求するか、参照プレイヤーと照合して確定する。
- RAM 更新をファイル読込時にまとめて適用しない。再生途中の上書きも、
  VGM の命令順・wait の位置で反映する。
- バンクの連結、ループ時の重複蓄積防止、転送元・転送先の範囲、
  切れたブロック、`0x68` の長さ 0 の特別扱いをテストする。
- 圧縮データブロックと RF5C164 向け `0x90〜0x95` は追加段階。
  初期段階で遭遇した場合は未対応を明示し、完全対応とは表示しない。
  VGZ の gzip 展開と VGM 内の圧縮データブロックは別機能。

## ライフサイクルと表示

- 新規ファイルと先頭からの再生では RAM・レジスタ・リサンプラー状態を初期化する。
  チップ単体 reset の RAM 保持方針と、Player の曲初期化を明確に分ける。
- 一時停止は保持、VGM の途中ループも RAM とチップ状態を保持する。
- Genesis エンジンに RF5C164 を任意追加し、通常の Mega Drive ファイルでは
  PCM コアを必要としない構成にする。PCM 単独の VGM も想定する。
- エンジンの再利用条件に PCM の有無と各クロックを含め、曲切替で作り直す。
- Analyzer に `PCM On / Off` を追加する。Off 中も内部の時間を進め、
  復帰時はその位置から鳴らす。全音源ミュート判定に PCM を加える。
- 8ch の設定表示・Snapshot は再生接続後に追加。
  書き込み監視で表示する場合は、選択チャンネルを解釈して状態を保持する。
  実音量や現在の再生アドレスは、レジスタ設定だけでは取得できない。

## 実装順序と完了条件

1. **コア単体**: 採用元を固定して WASM 化。合成波形で発音、符号、パン、
   ピッチ、ループ、RAM バンク、8ch 合算、reset を確認する。
2. **VGM 接続**: 上表の命令を実装し、合成 VGM で途中の RAM 更新、
   分割ブロック、再スタート、曲切替、途中ループを検証する。
3. **Genesis ミックス**: FM / PSG / PCM の同時再生、クロック反映、
   PCM ミュート、出力レート変換、クリッピング・音量バランスを確認する。
4. **Analyzer と配布**: 音源検出、PCM ボタン、未対応表示を接続。
   `web/` → `docs/js/` 同期と WASM・パッケージ収録を更新する。
5. **実曲比較**: 使用命令を確認した Mega-CD VGM で参照プレイヤーとの
   音声比較とブラウザー聴取を行う。曲名・使用命令・比較結果を記録する。

初期完了は 1〜5。チャンネルモニター、圧縮ブロック、DAC stream、
公開 `vgm_runtime.js` への自動選択接続、Playground 高レベル API は後続段階。
既存の YM2612 DAC、PSG、YM2608 ADPCM-B の関連テストも実行し、
共有パーサーの変更による回帰がないことを確認する。
