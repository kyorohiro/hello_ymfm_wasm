# PC Engine CD-ROM²: PSG + ADPCM + CD-DA

Date: 2026-10-28

`todo_cdromrom_01.md`の音声範囲を完了。前段のCD-DAへMSM5205を追加し、
Playgroundの **PC Engine CD-ROM²** modeでHuC6280 PSG・ADPCM・CD-DAを同時に使える。
Browser／Native、Main／Worker、offline WAV出力へ接続した。
使い方は[../msm5205.md](../msm5205.md)、CD-DAは[../cdda.md](../cdda.md)。

## Implementation

- `native/msm5205/`にC11共通coreを追加。既存のBSD libvgm由来JS decoderを移植し、
  raw FIFO／reset／3・4bit／prescaler／external VCLK／整数演算を維持。
  Analyzerの従来JS・VGM command・既存chip gainは変更していない。
- PC Engine向けに64KiBの符号化済みRAM、nibble単位の範囲、loop、16段階rateを追加。
  default clockは既存互換の1,536,000Hz。rate12が8kHz、rate15が32kHz。
  hardware資料のclock例と、この互換baseline・便宜的なRAM APIを区別して文書化。
- WASM3590bytes、固定128KiB memory、128frame scratch、host importなし。
  render中の確保・拡張・ファイル読込・UIへのblock要求はない。
- Browserは既存AudioContext、Nativeは既存audio callback、offlineは同じoutput frame時計を使用。
  `huc6280`／`msm5205`／`cdda`の独立Mixer。新モードのPSGは既存PC Engineの0.44を継承し、
  ADPCM／CD-DAはunity。新しい測定値として扱わず、既存校正値も変更しない。
- `adpcm.loadMemory`／`loadSample`／`play`／`stop`／`reset`／`writeRegister`／`getState`。
  `pg.msm5205`も利用でき、OPN／X68000の従来`adpcm`は維持。
- WAV／PCMをmono・指定rateへ変換し、high-nibble-firstの4bit ADPCMへ符号化。
  RAMと入力PCMの上限を確保前に確認。符号化・転送は準備時のみ。
- Stop時に古い予約発音・準備・uploadを取消。失敗した置換は旧sourceを維持し、
  旧generationのlate begin応答はupload IDを取得してから中断する。
  予約Mixは維持し、旧sourceへのraw writeが新sourceを壊さない。
- Native RAMはcurrent／retained／staging合計128KiB。最後のsource ownerの解放はcontrol thread。
  app側はC/H/LICENSE/NOTICEをpinし、standalone source ZIPとoffline検証へ含めた。
- 新modeのstarterと`examples/pc-engine/pce-cd-three-sources.js`は元音声を生成する。
  音声ファイル・game disc・BIOSなしで3系統を比較できる。index.jsからMixerを上書きしない。

低レベルのraw decoderは互換性上reset predictorが-2。無準備のPCE hostでは`stop()`して
strict zeroにし、他modeへDCを追加しない。Coreの互換演算は変更していない。
loopはADPCM predictorを継続するため、任意のraw sampleの切れ目は音量変化やclickの原因になる。
Exampleは25msのfadeで末尾stepを0へ戻し、繰り返しても音量が増えないことを確認した。

## Validation

- 実C11／C++14／WASM：44.1／48kHzでraw PCM・全状態が従来JSと一致。
  各1323commands／31488frames。PCEの全16rate、別clock、奇数nibble開始・長さ、
  EOF、loop、mute／gain／reset、任意block分割もNative／WASMで一致。
- 実HuC6280＋MSM5205＋CD-DAのoffline合算・frame予約・分割不変性・WAV出力3試験が成功。
- Web／Playground関連4636件、音声core＋unit用`npm run test:cdrom2`55件、全mode型fixtureが成功。
- Chromium153.0.8010.12／WebKit26.6の全8route：単体44.1／48kHz、実Playground Main／Worker。
  Worklet捕捉PCMと直接WASMの誤差0、3系統の周波数・各strip・mute／pan・音量維持・
  Stop後exact zero・再Run・実starterを確認。全292served sourceのhashが最終treeと一致。
- WorkerのPSGは既存lookaheadがあるため、試験は0.65秒分の実audio frameを進めてから比較。
  新しいpolling／UI書き戻しは追加していない。
- 共通callback／event queueへの追加の回帰確認として全Cargoを実行：780成功／0失敗／4既存ignore。
  MSM5205新規9件にはC ABI、44.1／48kHzの実3系統callback、置換・Stop・旧raw write取消を含む。
- TauriのPython28件／Node31件、全24offline pin、1975fileのNative source ZIP照合が成功。
- npm開発配布物は318modules、28chip pairs＋CD-DA／MSM5205、367declarations、929files。
  隔離installで実ADPCM／CD-DA WASM、EOF、rate、予約、公開型を確認。
- CIへapp-owned音声coreのbuild／parity／unit jobを追加。既存SDK検証は29artifact／57outputsを維持。
  repository referenceだけ、別管理のCD-DA／MSM5205完全pairを専用ABI・hash付きで認識。
  candidate／prebuiltは厳密なまま。既存97＋追加8のCI guard全105件成功。remote CIは未実行。

物理出力は捕捉後mute。人による実聴、実機比較、Tauri GUI操作は未実施。
