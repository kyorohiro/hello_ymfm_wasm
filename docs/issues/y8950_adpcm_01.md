# Y8950 ADPCMのPlayground対応

2026-10-24。MSX Audioの主音源と、`createSoundChip('y8950')`で追加した音源から、
Y8950のADPCM-Bを使えるようにした。Browser／Native・Main／Workerを同じAPIへ接続した。

## API

```js
const chip = await useSoundChip('y8950'); // MSX Audioなら主音源を借用する。
const sample = await chip.adpcm.loadSample(pcm, {sampleRate: 16000});
chip.adpcm.setVolume(160);
chip.adpcm.keyOn();
await sleep(sample.duration);
chip.adpcm.keyOff();
```

- `adpcm.loadMemory(bytes, address = 0)`：エンコード済みADPCM-Bの転送。最大2 MiB。
  `Uint8Array`／`ArrayBuffer`を受け取り、ADPCMを停止して既存データの指定範囲だけを置換する。
- `adpcm.clearMemory()`：ADPCMを停止してサンプルメモリーを消去する。
- `adpcm.loadSample(source, options)`：PCM／AudioBuffer／WAVなどをモノラルへまとめ、
  ADPCM-Bへエンコードして転送し、再生範囲・速度を設定する。自動では発音しない。
- `adpcm.setSample({start, end})`：バイト単位の範囲`[start, end)`。
  8-bit DRAMモードを使い、両端は32バイト境界。レジスター8のFM設定は維持する。
- `adpcm.setDeltaN(value)`／`setPlaybackRate(samplesPerSecond)`：速度と音程を変更する。
  レートは`Delta-N × clock / (72 × 65536)`。量子化後の実レートを返す。
- `adpcm.setVolume(0..255)`、`keyOn({repeat = false})`、`keyOff()`、`reset()`。
  Y8950はモノラル1ストリーム。repeatは範囲全体の繰返しで、独立したloop pointはない。
  ADPCMだけのresetはFM・サンプルRAMへ影響させない。

YM2608のADPCM-Bエンコーダー・PCM読込みは再利用するが、レジスター配置と分周はY8950専用にする。
存在しないstereo panやlimitレジスターを他音源のAPIで代用しない。
他のOPLチップには`adpcm`を公開しない。

## 寿命・音声処理

- 転送・消去はPromiseで完了を待つ。NativeではIPC受付ではなく、コアへの適用完了を待つ。
  メモリー転送は未来の発音予約とは分け、通常のレジスター命令は既存の演奏時計に従う。
  転送の適用とADPCM停止を一度に行い、Workerの未来時刻のkeyOffより先に転送されても、
  それまでの発音が新しいデータを途中から読み始めないようにする。
- 呼出し時のバッファを保持用にコピーする。decode／転送待機中のStop・dispose・loop取消しで、
  古い音源へ後続の範囲設定・発音を書き込まない。同IDで作り直した音源とも分離する。
  URL取得後のdecodeも元の所有者で実行する。`pg.stopAll()`はRun tokenを変えないため、
  読込み専用の世代でも取り消し、同じクライアントで次の読込みを始められるようにする。
  エンコードから転送完了までにclockが変わった場合は、範囲・Delta-Nを設定せずエラーにする。
  サンプルは新しいclockで読み込み直せる。
- Nativeのメモリー準備・最終解放は制御側で行う。
  追加音源のRAM・待機payload・退役待ちは既存の16台／64 MiB予算へ含める。
  MSX Audioの主音源用RAMは、他の主音源と同様に追加ラックの予算とは別枠にする。
- ADPCM単独でも出力を開始する。Stop・owner取消しでADPCMを停止し、
  別loopやFMの所有者まで停止しない。親チップのresetではサンプルRAMを保持する。
  親チップの`allNotesOff()`は、FM・rhythmに加えてADPCMも停止する。
- 初期音量の校正値、既存のFM出力、Browser／Directの同期`read()`／`generateStereo()`は変更しない。
  音色情報の常時pollingや、ADPCM専用の別AudioContextは追加しない。

## NativeのサンプルRAM

4 KiBのページを制御側で準備し、音声callbackでページpointerを交換する。
部分更新の最大2境界ページだけは、適用時の内容をコピーしてから指定範囲を書き換える。
これにより、準備後にraw CPU data portへ書いた隣接バイトも保持する。
全2 MiBのcopy／zero fill・ページ確保・最終解放はcallbackへ持ち込まない。
古いページも制御側のpoolで保持し、callbackが参照しなくなった後に制御側で回収する。

追加ラックでは準備中・適用済み・退役待ちと転送payloadを予算へ数える。
待機payloadのguardを回収した後でもう一度ページを回収し、使い終えた予約が次の転送を妨げないようにする。
未受理トランザクションには完了待機者がいないため、そのpayloadを待機用に残さない。

メモリー転送・消去はADPCM decoderを停止してから交換し、FMは止めない。
出力側が直前の生成sampleを保持している場合は、次のチップ更新までの保持をWASMと一致させる。
交換した新しいRAMを、以前のADPCM streamが読み続けることはない。

## 追加：音源タブとKeyboard

Y8950タブへADPCMの編集・試奏を追加した。MSX Audioの主音源と、
`createSoundChip('y8950')`の独立インスタンスで同じ操作を使う。

- 「Open Sample Editor…」から既存の共通エディターを開く。
  ファイル入力・マイク録音・波形の範囲選択・gain・fade・手描き・音程推定を再利用し、
  選んだ音声をADPCM-Bへ変換して、指定したRAM開始位置へ転送する。
  変換先の初期選択はADPCM-Bにし、別モードで保存した変換先も意図せず引き継がない。
  Nativeの共通エディターも既存のPCM/WAV読込み・圧縮音声用Offline decoderと、
  Nativeのsample busへ接続した。preview用の一時bankは終了・取消し・Stopで回収し、
  音源の演奏をWeb Audioへ迂回させない。
- タブで32バイト境界のstart／end、Delta-N／実レート、音量、範囲全体のrepeatを編集する。
  読込みは自動では発音しない。音量が0なら音量を上げてから試奏する。
- Hold to play／Release／1秒のpreviewと「Use Keyboard」に対応。
  共通KeyboardのChip／CH選択にも「ADPCM sample」を追加した。
  Guitar／PCキーは設定済みの範囲・速度をトリガーし、MIDI音程で転調しない。
- FMとADPCMは別のmanual leaseを使う。Native内部ではADPCMをchannel 23へ割り当て、
  FMの保持状態と分離した。古いnoteOffや遅い読込み結果で新しい発音・接続を変更しない。
  タブの非表示・選択変更・Stop・disposeで、その操作が持つ試奏や読込みを終了する。
- reg8のFM上位2bitとADPCM下位6bitを独立に保護する。
  ADPCMの設定・試奏でFM／CSMを変更せず、FM側の古いレジスター値でもADPCMを上書きしない。
- 波形は制御側でエンコード済みデータから最大512点へまとめる。
  音声callbackやreadbackでサンプル全体をdecode／copyせず、新しいpollingも追加しない。
  再生範囲とRAM revisionが一致する時だけ表示し、raw CPU書込みや別の範囲ではunknownにする。
  Nativeのupload revisionと現在のrevisionを分け、転送ACKまでのCPU書込みも誤表示しない。
  「Gate on」は適用済みの発音命令であり、EOS後まで実際の再生継続を保証する表示ではない。

Browser／Native・Main／Workerの経路へ接続した。
Mixerの初期値や保存preset、FM音源の計算、同期`read()`／`generateStereo()`は変更しない。
