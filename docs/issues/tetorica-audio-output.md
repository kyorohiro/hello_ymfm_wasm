# Tauri Playground の音声出力選択

2026-10-10。通常は WebView/Web Audio 出力を使い、メニューから Audify と出力機器を選べるようにする。

## 実装

```text
既存の音源・ミキサー・エフェクト・STOPフェード
  → 出力AudioWorklet
  → 上限付きPCM転送
  → 同梱Node / Audify
  → 選んだ物理／仮想オーディオ機器
```

Tauri 側に実装し、ブラウザー版の出力は変更しない。
WebView 出力が起動時のデフォルト。Audify を選ぶと機器一覧を表示し、Apply output
で接続する。切り替え時は演奏を停止し、Run で再開する。
機器は毎回列挙し、IDを再起動後まで保存しない。ステレオ出力できる機器が対象。

Web Audio の処理を保つことで、既存のチップ・音色・サンプル・FX・Main/Worker の
機能をそのまま使う。WebView のスピーカー出力は Audify 接続後に外すため、二重に鳴らない。
レートが違う場合は機器の推奨レートへ線形補間する。

接続は127.0.0.1の一時ポートと実行ごとのランダムトークンを使う。
音声は最長4ブロックまでのクレジット制御とし、転送が追いつかない場合は古い音を
蓄積しない。接続エラー・切断時は演奏を停止する。再読み込み・終了時に出力を閉じる。
制御はTauriのローカルメインウィンドウに限る。Nodeには任意コマンドを渡すAPIを設けない。

## 検証

- PCM上限・停止後の再開・ステレオの並び・44.1kHzからのレート変換を単体テスト。
- Audifyのプロセス全体の警告を、別インスタンスのストリーム異常と誤認しないよう修正・テスト。
- 実際のCoreAudio機器へ小音量で送出し、Main/Workerの演奏、機器選択、キュー上限、
  WebViewへの切り戻し、接続切断からの停止を確認。
- 機器一覧には内蔵出力、BlackHole、ZoomAudioDeviceが表示された。
- Tauri側のPythonテスト8件・Nodeテスト14件、上流のAudify関連テスト10件が成功。
- リリース版アプリのビルドが成功。同梱リソースのNodeで機器一覧を取得し、
  実際のTauri WebViewからBlackHoleへ接続。Main/WorkerのRun/StopとWebViewへの
  切り戻しを確認。終了時に音声プロセスが終了することも確認。

## 残る点

- 追加の音声転送・バッファがある。ライブ本番向けの往復遅延・長時間音切れの測定は未実施。
- 外部クロック同期、複数出力への同時送信、出力チャンネル割り当ては今回の対象外。
- 別アプリへ送るには仮想機器と受け側の入力設定が必要。ドライバーの導入は行わない。
- 検証はmacOS/arm64。Windows/Linuxは実機未検証。
- 同梱するNodeとAudifyのネイティブモジュールはビルド先のOS/CPUに合わせる。
- npm/GitHub/itch.ioへの公開はこの実装では行わない。
