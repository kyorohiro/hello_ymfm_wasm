# Performance Audit — リアルタイム音声処理

Tetoricaのリアルタイム音声処理について、パフォーマンス監査を実施してください。

## 目的

明らかに無駄な処理、不要なメモリ確保、過剰なデータコピー、処理遅延などを発見し、継続的にパフォーマンスを改善できる状態にすることです。

現在発生しているノイズ問題の原因特定とは独立した調査です。

## 調査対象

既存コードを調査し、特に以下を確認してください。

- AudioWorkletのリアルタイム処理
- JavaScriptとWASM間の呼び出し
- PCMバッファの生成・コピー・再利用
- 音源エミュレーターの呼び出し経路
- Main / Worker間の通信
- イベントスケジューリング
- GCやメモリアロケーション
- 音源・チャンネル切り替え時の処理

上記以外にも、明らかな問題があれば調査対象に含めてください。

## 調査方針

1. まず既存コードと処理経路を理解してください。
2. 推測だけで問題と判断せず、可能な範囲で測定してください。
3. 平均処理時間だけでなく、最大遅延や処理時間のばらつきも確認してください。
4. 改善効果と、既存仕様を壊すリスクを評価してください。
5. 効果が不明確な最適化は推奨しないでください。

## 制約

- 今回は本番コードを変更しないでください。
- 音源の演算精度や再現性を犠牲にしないでください。
- 既存APIやチャンネル管理仕様を変更しないでください。
- 調査範囲を無制限に広げず、影響が大きい箇所を優先してください。
- 問題が見つからなければ、そのまま報告してください。

## 報告内容

各改善候補について、以下を整理してください。

- 対象ファイル・関数
- 現在の処理と問題点
- 測定結果または根拠
- 想定される改善方法
- 期待できる効果
- 変更リスク
- 優先度

最後に、**効果が大きく、変更リスクが小さい改善候補**を優先順にまとめてください。
