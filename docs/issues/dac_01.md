# DAC ストリームの対応状況と残課題

## 位置づけ

VGM Analyzer の DAC ストリーム対応は、複数チップ再生・解析対象の拡充より後に進める。
この文書は現状と今後の作業を整理するもので、対応完了を意味しない。

更新: 未対応ストリームの設定で例外を投げる挙動を変更した。該当ストリームだけを無効化し、
Analyzer の専用警告欄へ表示して他の演奏を続ける。警告は曲の切り替えでクリアする。
ストリームを省略した分の音は欠けるため、完全な再生とは区別する。

DAC ストリームは、VGM のデータブロックから値を読み、指定した周波数でチップのレジスタへ書き込む仕組み。
例えば「音声データを毎秒8,000回、指定レジスタへ送る」といった処理を、個々の書き込みを列挙せず表現する。
名前に DAC とあるが、YM2612 の DAC に限った機能ではない。

| VGM 命令 | 用途 |
| --- | --- |
| `0x90` | 送り先チップ・インスタンス・ポート・レジスタの設定 |
| `0x91` | データバンク・ステップ幅・ステップ開始位置の設定 |
| `0x92` | 書き込み周波数の設定 |
| `0x93` | 開始位置・長さ・モードを指定して開始 |
| `0x94` | 停止（`0xFF` は全ストリーム停止） |
| `0x95` | バンク内のブロック番号を指定して開始 |

通常のレジスタ書き込み、ROM/RAM データブロックの読み込み、チップ自身の PCM/ADPCM 再生とは区別する。
**Y8950 の ADPCM メモリ読み込みと再生は対応済み**であり、DAC ストリーム未対応という理由だけで MSX の ADPCM 再生ができないわけではない。

## 現状

調査対象: `web/ym2612vgm.js` と、それを使う `web/vgmplayer.js`。

| 対象 | 現在の挙動 |
| --- | --- |
| YM2612 | 基本的なストリーム書き込みは実装済み。ただし命令仕様への対応に不足がある |
| 32X PWM | 専用処理あり。16-bit データ単位、長さモード、逆再生、ループなどの実装・テストあり。完全対応を保証するものではない |
| YM2413、YM3526、YM3812、Y8950、YMF262 | 警告を表示し、該当ストリームを無効化。他の演奏は続行 |
| YM2151、AY | 警告を表示し、該当ストリームを無効化。他の演奏は続行 |
| RF5C164 | 設定時に警告して無効化。他の演奏は続行 |
| その他（YMF278B、OPN 系の他チップ、PSG など） | 送り先への配送は未対応。警告して無効化し、YM2612 への誤配送を防ぐ |

対応する送り先は第1インスタンスの YM2612 (`0x02`) と PWM (`0x11`) に限定する。
他の送り先・第2インスタンスは警告して無効化し、開始命令や高速開始命令でも再有効化しない。

## 優先して直す問題: 誤配送

以前は `#performStreamWrite()` が PWM と RF5C164 以外の送り先を
`targets.ym2612 || targets` に渡しており、未対応チップの値を YM2612 へ誤配送する可能性があった。
設定時の対応 ID 判定、開始時の無効化判定、配送時の YM2612 ID 確認で修正した。

- [x] 対応するチップ ID を明示し、未対応 ID を YM2612 へ流さない。
- [x] 警告にチップ ID、インスタンス番号、ストリーム ID を含める。
- [x] 未対応ストリームでも解析を継続し、再生はそのストリームだけ省略する。
- [x] 通常ステータスに上書きされない警告欄を UI に設ける。同一警告は重複表示しない。

破損した VGM や命令の途中で切れたファイルなどのエラーは、引き続き停止対象とする。

## YM2612 を含む共通処理の不足

PWM 以外の `#startStream()` / `0x95` 処理には、次の残課題がある。

- [ ] `0x91` の `stepBase` を反映する。
- [ ] `0x93` の長さを、命令数・ミリ秒・データ末尾まで・長さ変更なしの各モードに従って扱う。
      現状は長さを実質的にバイト範囲として扱っている。
- [ ] 開始位置 `0xFFFFFFFF` の特別な扱いを実装する。
- [ ] 逆再生モードを実装する。
- [ ] `0x95` のブロック選択を、`0x91` で指定したバンク内の番号として扱う。
      現状の非 PWM 経路は共通の `dataBlocks[blockId]` を参照している。
- [ ] `0x95` のループフラグを正しく変換する。
      現状は flags をそのまま渡す一方、開始処理はループを bit 7 で判定している。
- [ ] 初回書き込みのタイミングを統一する。
      PWM は開始時点に書き込むが、非 PWM 経路では最初の周期を待つため、仕様・参照実装と照合する。
- [ ] 予約ストリーム ID `0xFF` の扱いを確認する。全停止以外の命令では予約 ID を通常のストリームとして扱わない。

## 複数チップ設計との接続

通常の MSX 書き込みは、種類とインスタンス番号で対象を解決する経路を追加済み。
DAC ストリームも同じ登録先へ接続し、特定の単一エンジンに依存しない構成にする。

- [ ] `chipType` の下位7ビットをチップ種類、bit 7 を第2インスタンスの指定として扱う。
- [ ] `resolveChip(type, index)` / `getVgmTarget(type, index)` へストリームの書き込み先を接続する。
- [ ] `VgmPlayer` の `consumeWait()` に渡す targets にも、インスタンス解決を引き継ぐ。
- [ ] チップごとのコマンド形式・データ幅・必要なチャンネル選択をアダプターで扱う。
- [ ] 未登録のインスタンスを第1チップへ代替配送しない。

同一チップ2基を表現できる設計は維持するが、今回の方針では2基構成の実再生検証は対象外。
設計上の対応と検証済みの再生構成は区別して記載する。

## 対応順序

1. 未対応チップへの誤配送を防ぐ。（対応済み: 警告して該当ストリームを無効化）
2. YM2612 の共通ストリーム処理を仕様に合わせる。既存 PWM 処理も回帰確認する。
3. 複数チップのインスタンス解決とストリーム配送を接続する。
4. 必要な実曲を選び、AY・Y8950・YM2413 などの送り先を順次追加する。
5. Analyzer にストリームの送り先、周波数、バンク、再生区間を表示し、調査できるようにする。

MAME の新しいコアを追加する作業とは分離する。まず既存コアを使う Player 側の問題として扱う。

## 検証項目

- 未対応チップのストリームで YM2612 の書き込みが発生しない。
- 合成データから期待する値列・時刻を求め、実際のレジスタ書き込みと比較する。
- 同じ曲を直接書き込みとストリーム命令で表現し、対応範囲内で出力が一致する。
- 開始・停止・全停止・再開・ループ・逆再生・周波数変更を確認する。
- 複数バンク、バンク内ブロック番号、ステップ幅・開始位置を確認する。
- 通常再生、分割レンダリング、リセット、シークで結果が一致する。
- 既存の MSX 複合再生、Y8950 ADPCM、YM2612 DAC、PWM 再生を壊さない。
- 実曲による確認結果を、合成データのテスト結果と分けて記録する。

## VGM Parser → Mock Chip の自動テスト

音源コア・WASM・AudioContext を起動せず、VGM バイト列を `playStep()` と
`consumeWait()` に渡し、Mock チップが受け取った命令を検証するテストを追加した。

```sh
node --test web/vgm-parser-mock.test.mjs web/dac-warning.test.mjs
```

- テスト本体: [vgm-parser-mock.test.mjs](../../web/vgm-parser-mock.test.mjs)
- 共通補助: [test-support/vgm-mock.js](../../web/test-support/vgm-mock.js)
- 記録形式: `{sample, chip, instance, method, args}`。`sample` は VGM の 44,100 Hz 時間単位。
- 全チップの配送を同じログに記録し、余計な書き込みや別チップへの誤配送も比較で検出する。
- 期待するチップ、ポート、レジスタ、値、時刻はテスト側で明示する。
  パーサーのイベントや内部定数から期待値を生成しない。
- `web/` とブラウザー配信用 `docs/js/` のパーサーに同じケースを適用する。

| 対象 | Mock テストの範囲 |
| --- | --- |
| 通常レジスタ書き込み | 20形式の送り先・ポート・値。PWM の12-bit値も含む |
| wait | `0x61`、`0x62`、`0x63`、短縮 wait の後の絶対時刻 |
| 終端 | `0x66` より後のデータが配送されない |
| MSX 複合命令 | AY・YM2413・Y8950 の交互書き込みと順序 |
| ADPCM | Y8950 のロード先、オフセット、メモリサイズ、データ内容 |
| reset | 再実行時の命令・時刻ログの一致 |
| PWM ストリーム | 開始時と周期境界の書き込み、wait 分割方法に依存しない結果 |
| 不完全な命令 | 命令途中で切れた場合、その書き込みが Mock に届かない |
| 未対応ストリーム | 既存の `dac-warning.test.mjs` で省略・警告・演奏継続を検証 |

追加手順:

1. 手で追える最小の VGM 命令列を作る。
2. 期待する書き込み列と時刻を、仕様に基づいて明示する。
3. 不具合修正では、まず修正前にテストが失敗することを確認する。
4. 修正後に関連テストを実行し、ブラウザー配信用コードも同期する。

この層は命令の解釈と配送の検証であり、実チップの音質・実曲の再現性を保証するものではない。
同一チップ2基の実再生検証は従来どおり対象外。今回の Mock は第1インスタンスだけを登録している。
YM2612 DAC ストリームの未修正の仕様不足について、現在の誤った挙動を正解として固定するテストは追加していない。
上の未完了項目ごとに仕様ベースのケースを追加していく。
