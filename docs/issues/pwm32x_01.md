# 32X PWM：MAME 由来の共通コア

2026-10-07。最初の段階として、独立コアと VGM 比較経路を実装。

- 元実装: MAME `mega32x.cpp` / `mega32x.h`、revision `df862b468443b391b24405c322aea60695d1825e`。
- BSD-3-Clause、David Haywood。元ソース・ライセンスは `third_party/mame-32x-pwm/`。
- `web/pwm32x.js` は CPU / DOM / AudioContext / WASM に依存しない JavaScript コア。
- 3段 FIFO、満杯時の古い値の破棄、周期による取り出し、左右ルーティング、underrun時の保持、制御／周期変更時の FIFO リセットに対応。
- 周期は `cycle - 1` input clocks。cycle 0は4095。割り込み周期はカウントのみで、SH2へのIRQやDMAは実装しない。
- 出力は固定12bit DACの `value / 2048 - 1` と既定gain 0.4。最初のDAC書き込み前は無音。出力フレーム内を時間平均し、アナログPWMフィルターは再現しない。
- MAMEのホスト側整数Hzタイマーへの変換は使わず、入力クロック単位で進める。このホスト出力はMAME全体や実機との完全一致を意味しない。

## 使う

ローカル開発版の `createSoundChip('pwm', {clock, sampleRate})` は音声デバイスなしで作成できる。
`writeRegister(0..4, value)`、`read(register)`、`generateStereo(frames)`、`reset()`、`saveState()` / `loadState()`、`dispose()`。
Worklet内からもこのコアを直接importできる。`execution: 'worklet'` の共通factoryにはまだ未接続。

VGM は `createPlaybackEngine(vgm, {getFactory, pwmModel:'mame'})` または
`GenesisAudioEngine.create({...factories, pwmModel:'mame', pwmClock})` で選択する。
Analyzer／CLIのVGM既定は `mame`。従来方式は `pwmModel: legacy` で選べる。`mame` 選択時のVGM出力は `pwmOutputMode: duty` とgain 1で、従来方式と同じcycle基準の振幅に揃える。元MAMEの固定DAC換算は `pwmOutputMode: dac` で選べる。Sample Explorerのプレビューも従来方式を維持。

[比較ページ](../demos/32x-pwm-compare.html) は Genesis構成のVGM / VGZから先頭10秒の2方式を生成し、試聴・WAV保存できる。

```sh
node scripts/compare_pwm.mjs /path/to/song.vgz output/pwm-comparison 10
```

`-legacy.wav`、`-mame.wav` と、入力SHA-256・clock等のJSONを出力する。
初期の比較ではMAMEの固定12bit DAC換算とgain 0.4を使ったため、PWMとFM／PSGの音量バランスが変わっていた。現在の比較ではcycle基準の換算を揃え、FIFO／タイマーとルーティングの違いを比較する。
「20 Victory.vgz」の音量補正後の利用者確認を受け、2026-10-08にAnalyzer／CLIのVGM既定を新方式へ変更。実機との一致は引き続き未確認。

## 実曲での音量比較（2026-10-07）

利用者提供の「20 Victory.vgz」（Virtua Fighter / Sega 32X）で開始位置と長さを確認。
両方式とも先頭から475136フレーム、53267 Hz、約8.92秒。カット位置は同じ。
cycle 1047では固定DAC出力のPWM振幅が従来方式の約0.102倍になり、FM／PSGとのバランスが変わった。
比較用のduty換算に変更後、左チャンネルのAC RMSはlegacy 0.052471、mame 0.052323、同位置の相関は約0.984。
入力の音楽ファイルはリポジトリに追加していない。聴感改善の利用者確認と実機比較はまだ別途必要。

固定DAC出力も調べる場合:

```sh
node scripts/compare_pwm.mjs /path/to/song.vgz output/pwm-dac 10 dac
```

## VGM 既定の切り替え（2026-10-08）

- createPlaybackEngine の既定を mame / duty へ変更。PWMヘッダーのないGenesis曲は従来のゼロ出力を維持し、新PWMコアを生成しない。
- CLIの既定出力が、利用者確認済みの「20 Victory.vgz」のmame / duty WAVとバイト単位で一致。
- 従来方式は pwmModel: legacy、元MAMEの固定DAC換算は pwmOutputMode: dac で指定できる。
- Sample Explorerのプレビューと独立GenesisAudioEngineの既定は、この変更の対象外。
- npmへの公開、Tauriリポジトリへの取り込みは別作業。

既定切替の回帰確認: PWM／MAME元関数／状態復元27件、共通再生／ミュート／区間出力12件が成功。確認用Analyzer ZIPを再生成し、382参照を照合。
配布物の実画面でも「20 Victory.vgz」が既定PWM32X／dutyで再生され、停止できることをChromiumで確認。

## MegaSynth / Playground / Node の接続（2026-10-08）

- MegaSynth({mega32X: true}) は専用PWM AudioWorkletをmasterInputNodeに接続し、既存FX・マスター出力へ混合する。pwm APIはstart後に利用可能。
- PlaygroundはuseSoundChip('pwm')。Main／logic WorkerのどちらからもMessagePortで専用Workletへ直接命令し、PCMをMainへ戻さない。型定義とgenesis/32x-pwm-sine.jsを追加。
- MegaSynthNode({mega32X: true}) は既存の音声WorkerでPWMを生成し、FMと混合してnativeFXへ渡す。render()でWAV化でき、connectOutput()でAudifyや利用者の出力へ接続できる。
- PWM32XPlaybackは共通のMAMEコアに出力フレーム単位の書き込みキューを加える。scheduleWrites(entries)のframeは、命令を受け取った時点の次の出力フレームを0とする。タイマー・MainへのPCM転送は使わない。
- createSoundChip('pwm', {execution: 'worklet'}) + PWM32XWorkletTransport、およびPWM32XAudifyTransportも用意。DirectTransportは明示的なPCM生成用。
- 既定の統合出力はmame / duty / gain 1。低レベルPWM32Xの既定dac / gain .4は維持。Core・ホスト音量の違いは引き続き明示する。
- PWMはFMイベントrecordingやイベントlooperの記録対象には含めない。NodeのPCM looperは混合したFM/PWMを収録する。

検証: Node Worker／オフラインMegaSynth／PWM WorkletのステレオPCM一致、分割レンダー、原子的なスケジュール検証、停止・再接続。Chromiumで共通WorkletTransport、MegaSynth混合・reset・再起動、Playground Main／Workerを確認。npm公開・Tauri配布物の更新は未実施。
