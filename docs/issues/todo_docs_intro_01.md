状態：Game Boy の Pulse / Envelope / Wave の試作ページを実装済み（2026-10-05）。Sweep / Noise、物理配置図、Analyzerからの専用導線は未実装。WaveのJSON配列コピー・貼り付けには対応。全体の設計メモと進捗を兼ねる。

## 背景と目的

音源チップの仕様や音作りを解説する資料はあるが、読むだけでは「この値を変えると、どう聞こえるか」が分かりにくい。レジスターの意味を理解することと、自分で音を作れることの間を埋めたい。

我々の目標は、**短い説明・操作 UI・動く JavaScript・実際の音**を一緒に提供すること。読者が別の開発環境を用意せず、その場でパラメーターを変え、音と波形の変化を確認できる解説にする。

最初の題材は Game Boy。これまで相談したパルス波、エンベロープ、スウィープ、32 点の波形メモリー、ノイズを扱う。将来的には YM2612 など他の音源へ広げる。

## 実機での物理配置と音の出口

API や波形の前に、「実機のどこで音を作っているのか」を説明する。音源の論理的な構成図だけでなく、本体・基板・IC・音源回路の位置関係を見せたい。

掲載したい図は次の二つ。

- **物理配置図**：本体の中の基板、音源回路を含む IC、アンプ、スピーカー、ヘッドホン端子の位置を示す。
- **信号の流れの図**：CPU からの設定 → 音源内部の各チャンネル → ミキサー・出力 → アンプ → スピーカー／ヘッドホン、という関係を示す。物理的な位置を表す図とは分ける。

Game Boy では、独立した音源 IC があると思わせないよう、APU が CPU と同じチップに内蔵されていることを説明する。一方、メガドライブの YM2612 のように独立した IC として搭載される例と比較すると、「sound chip」という呼び方と実装の関係が分かりやすい。

図を作る前に対象機種・基板リビジョンを決め、実機写真・回路図などで部品位置と接続を確認する。Game Boy / Game Boy Color や本体の世代による違いを、一枚の配置図で共通仕様のように扱わない。チップ内部の図も、機能ブロック図なのか実際のシリコン上の配置なのかを明示する。

解説画面では、配置図の音源部分から Pulse / Wave / Noise の説明と試聴へ進める導線を検討する。これにより、JavaScript の操作が実機のどの回路に相当するかを結び付ける。

資料の追加調査項目：対象基板の写真、IC の刻印と役割、音声出力の回路図、画像の掲載条件。出典と利用条件を確認してから掲載し、必要なら独自の模式図を作る。

## 我々が提供したい体験

1. 「どんな音が出る機能か」を短い日本語で読む。
2. 再生ボタンを押して音を聴く。
3. 一つのパラメーターを変更して、違いを聴き比べる。
4. 波形や時間変化の表示から、何が変わったかを確かめる。
5. 対応する JavaScript を読み、コピーするか Playground で編集する。
6. 詳しく知りたい人は、対応レジスターと参考資料へ進む。

最初からレジスターの数値列を読ませず、まず意味が分かる高レベル API を見せる。一方で「この設定はチップの何を操作しているのか」を確認できるようにする。

## Game Boy の解説案

| 題材 | 操作・比較したいこと | 理解してほしいこと |
|---|---|---|
| 実機の配置 | 基板上の IC・音源回路・音声出力の位置を見る | 音源がどこにあり、どこから音が出るか |
| 全体像 | Pulse 1 / Pulse 2 / Wave / Noise を個別に試聴 | チャンネルごとに音の作り方と利用できる機能が違う |
| Pulse | デューティ比を変え、同じ音程で聴き比べる | パルス幅によって音色が変わる |
| Envelope | 初期音量、`up / down`、`period` を変える | 発音後の音量変化。方向や周期がどのハードウェア設定に対応するか |
| Sweep | Pulse 1 のスウィープ設定を変える | ハードウェアによる音程変化。ソフトウェアで作るビブラートとの違い |
| Wave | 32 点・各 0〜15 の波形を表示・編集し、三角波やノコギリ波を比較 | 波形の形と再生する音程は別々に指定できる。波形中の周期構造によって聞こえる音の高さも変わりうる |
| Noise | ノイズの周期や LFSR の幅に関係する設定を変える | ノイズにも音色の違いがあり、打楽器の素材になる |
| 音作りの例 | 短いエンベロープや音程変化を組み合わせる | 個別の機能がキック、ハイハット、効果音などにつながる |

API の表記は実装済みのものを確認して採用する。存在しないメソッドやオプションを、動くサンプルとして掲載しない。

特に `setNote()` の説明では、32 点の繰り返し波形を使う場合と、録音した PCM の元の音程を基準に再生速度を変える場合を混同させない。

## Analyzer との連携案

VGM Analyzer の GB Info で得られる情報を、解説で試せる形へつなげたい。

- Wave：取り出した 32 点の波形を表示し、別の音程で鳴らす。
- Pulse / Noise：発音時の音色設定を持ち込み、値を変更して聴き比べる。
- 発音後の変化：音程・音量・デューティ比などの書き換えを、時間軸で確認する。

**発音時の設定だけで、元のゲームの音を完全に再現できるとは限らない。** 後続のレジスター書き換え、発音し直すタイミングなども音を作っている。静的な音色の抽出と、時間変化を含む再現を区別する。

最初は配列やコードのコピーで受け渡し、専用の読み込み UI や自動連携は後から検討する。サンプルには自作の波形・音色を用い、ゲーム由来のデータを無条件に同梱しない。

## ページと実装の方針

既存の `docs/introductions/` と [Playground 埋め込み処理](../introductions/playground-embed.js) を調査し、利用できる部分を再利用する。Tauri 専用にせず、まず Web 上で試せる内容にする。

- 一つのページで一つの仕組みを説明する。
- 操作 UI と表示コードの値を一致させ、コピーしたコードでも同じ設定を再現する。
- 再生はユーザー操作で開始し、停止・初期値へのリセットを用意する。
- 再実行やページ移動で、発音・ループ・音源インスタンスが残らないようにする。
- 実際の出力波形と説明用の模式図は、表示上も区別する。
- 音量は比較しやすく設定し、変更時のクリック音や過大な音量にも配慮する。
- ハードウェア自身の時間変化と Playground の時間制御を区別して説明する。

### Envelope / Wave追加

- Envelope：初期音量0〜15、up / down、周期0〜7を指定して2秒試聴。APU自身の時間変化とJavaScriptの停止時間を区別。内部音量を読んだことにせず、生成PCMの最大値−最小値を10 msごとに測って表示する。
- Wave：32点をキーボードでも操作できるスライダーで編集。自作の三角波・ノコギリ波・矩形波・32点内2周期の波形を用意。音程・4段階のレベルを指定して1.5秒試聴。編集値の図と生成PCMの図を分ける。
- Wave配列はJSONのみ受け付け、32点・各0〜15の整数を全検証してから反映。不正入力は現在の波形を保持。配列だけのコピーにも対応。Analyzerからの専用リンク・音色設定の持ち込みは未対応。
- 両ページで設定に追従するコードコピーとPlaygroundリンク、停止・リセットを実装。共通プレーヤーは準備中のStop・設定変更を無効化し、再生ノードを終了時に切断。pagehideでAudioContextを閉じる。
- 検証：実WASMで全波形プリセット・全レベル、Envelope増減・端点・周期0、44.1 / 48 kHz、コピーコードとのPCM一致、波形の周期構造と音名による音高変化を確認。共通プレーヤーの準備中キャンセル・連続再生・終了・Reset・非表示・離脱も自動テストで確認。計11件成功。
