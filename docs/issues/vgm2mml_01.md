# VGM Analyzer：人が読みやすいMML出力への改善

## 目的

現在のMML出力は、各イベントに音色・オクターブ・tick長・詳細コメントを繰り返すため、
人間が旋律やリズムを読むには冗長になっている。
本文を音符の並びとして読めるようにし、解析に必要な元データは別の詳細コメントへ整理する。

```mml
; 改善前の表記イメージ
@1
o3 d%80
r%32
@1
o3 a%80
r%32
@1
o4 c%80

; 改善後の表記イメージ
@1 o3 l8 q75
d a >c d
```

これは読みやすさの例であり、上記のtick値を無条件に8分音符へ変換する指定ではない。
変換可能な音価は指定BPM、グリッドとの誤差、発音間隔に基づいて判断する。

元VGMの完全な楽譜復元や外部MMLドライバとの互換性は目標にしない。
まずYM2612のCHごとの単音列を対象にする。PlaygroundでのMML再生は別途検討とする。

## 現在の実装と処理の分離

現在の `docs/vgm_analyzer/vgm_mml.js` は、VGMを直接読み、BLOCK/FNUMから音高を計算し、
その場でMML文字列を生成している。Analyzer画面の既存Note-ishイベントを入力にしているわけではない。
画面側のNote-ish音高推定とMML側の計算も同一ではないため、無条件に置き換えない。

既存VGM parserと現在のMML用レジスター解析を可能な限り維持し、次の責務に分ける。

```text
VGM parser
  → 音符イベント抽出（KEY操作、音高、音色、元の絶対サンプル時刻）
  → Musical Quantizer（音楽的な長さ、休符、gateの判定）
  → Musical Note Events
  → MML Writer（状態を保持して簡潔に整形）
```

Writer内ではVGMの生タイミングの解釈や量子化を行わない。
Writerは整形済みの音長・gate・音高・音色情報を受け取る。
元データへの参照は、詳細コメント生成のために保持する。

## 1. 音符イベント抽出

- 開始、KEY OFF、次の発音を区別し、整数の絶対サンプル位置として保持する。
- 音符の論理的な長さと、KEY ONからKEY OFFまでの長さを分離する。
- KEY OFFはレジスター操作時刻であり、リリースを含む可聴音の終了とは区別する。
- 明示的な再発音は同音でも残す。ピッチ変更による区間分割とは区別する。
- 小さなピッチの揺れをすべて再発音として出力しない。
  同一KEY区間内の微小変動をまとめる場合は、音高差・継続時間などの判定条件を定義する。
  半音境界付近の往復、実際の音程変更、明示的な再KEY ONを誤って統合しない。
- 画面側のNote-ish処理に流用できる判定があれば利用するが、既に安定化済みのイベント列が
  存在することは前提にしない。元の周波数変化は詳細情報に残す。

## 2. Musical Quantizer

### BPMとグリッド

BPMは従来通り手動指定、既定120。BPMの自動推定は今回行わない。
BPMは元データを音価へ換算する値であり、変更しても元のサンプル時刻を変更しない。

最初は4分・8分・16分・32分音符のグリッドを扱い、必要に応じて付点やタイで表す。
全CHで同じ時間原点を使い、開始位置と終了位置を絶対時間から求める。
区間ごとの丸め誤差を後続へ積み上げない。

### 許容誤差とフォールバック

最も近いグリッドへ常に丸めるのではなく、許容誤差内の場合だけ量子化する。
許容誤差はグリッドに対する割合と時間上限などで明示し、実装時に既定値・単位・根拠を記録する。
数値はこの文書では未確定であり、fixtureで妥当性を確認して決める。

連符、装飾音、細かいリズムなどがグリッドから遠い場合は、既存の `%tick` 表記を残す。
無理な量子化による音符の消失、順序の逆転、意図しない重なりを防ぐ。
開始位置・音長だけでなく、隣接する音符と休符の整合性も検証する。

### gateと休符の区別

短いKEY OFF後の空白を毎回独立した休符にすると、旋律が読みにくくなる。
ただし「短い空白」という理由だけでgateへ吸収しない。

- 複数の連続区間で発音間隔と発音割合が安定している場合にgate候補とする。
- 論理的な音長は次の発音までの間隔などから判断し、KEY OFFまでをgate長とする。
- 判定には最低反復数、空白の上限、発音割合のばらつきの許容値を設ける。
  具体値は実装時に記録し、境界ケースをテストする。
- 単発の空白、長い空白、不規則な空白、判断材料の足りない終端は休符を残す。
- gateの適用・丸めでKEY OFF時刻を近似した場合は、その誤差を詳細情報に残す。

## 3. 解析用MMLの記法

現在の形式は四分音符480tick、`o4 c` がMIDI 60、`%N` がtick長、`@N` が解析用音色ID。
`q`、オクターブ移動、タイはまだ定義されていないため、今回追加する解析用仕様として明記する。
特定ドライバの既存仕様に準拠しているとは表記しない。

| 記法 | 今回の定義 |
| --- | --- |
| `c8` / `r8` | 8分音符 / 8分休符 |
| `l8` | 省略時の音長を8分音符にする |
| `>` / `<` | オクターブを1つ上げる / 下げる |
| `oN` | 絶対オクターブ指定。MIDI 60は `o4 c` |
| `c4.` | 付点4分音符 |
| `c4^8` | 同音を再発音せず4分＋8分の長さで接続する |
| `q75` | 後続音符の論理長の75%をKEY ON区間とする。百分率、既定100 |
| `%N` | 四分音符480tickを基準にした明示的な長さ。量子化困難な区間に使用 |
| `@N` | 解析用音色ID。外部ドライバ向け音色定義ではない |

`q` は休符の長さを変更しない。タイで接続した音符は全体長に一度だけ適用する。
gateを使わない区間へ戻るときは `q100` を出す。
不明音程の既存表記 `?%N` と未変換要素の注記は維持する。
出力ヘッダーにも記法の概要を記載する。

## 4. MML Writer

CHごとに現在のoctave、default length、instrument、gateを保持する。

- `@1` などは初回と値が変わった場合だけ出す。
- octaveは初回を `oN`、以後は必要な場合だけ `oN` / `<` / `>` で表す。
- 同じ音価が続く区間は `l` を使う。頻繁な切り替えで冗長になる場合は音符に音長を付ける。
- gate判定できた空白は `q` で表し、独立した休符として重ねて出さない。
- 実際に残った空白は `r` で表す。
- 付点やタイは明示的な再発音と混同しない。タイが複雑になる場合は `%tick` も選択できる。
- 音符を適度な長さで改行する。拍子が不明なまま小節境界を断定しない。

### 本文と詳細情報

本文には旋律を追うための音符・休符・必要な状態変更をまとめる。
各音の長いコメントを本文に挟まず、CHごとの本文の後などに詳細コメントを分離する。

詳細情報には、音符番号との対応、元のサンプル開始位置・長さ・KEY OFF、
量子化後との差、統合したピッチ変化、音色の元レジスター情報を残す。
複数の元イベントを一つの音符へまとめた場合も対応を追えるようにする。
DACや未変換操作の要約・警告は従来通り保持する。

## 5. 実装範囲と進め方

最初の対象はYM2612、CH単位の単音列、音符と休符、octave、default length、
音色変更、基本量子化、保守的なgate検出とする。

次は今回の対象外とする。

- CH3特殊モードの完全な複音変換
- DAC、PSG noiseの音符化
- ベンド、ポルタメント、ビブラートの完全復元
- 高度なループ・パターン検出、和音・スケール推定

既存のVGM parsing/playback、Note-ish表示、TFI/preset抽出、その他のAnalyzer機能を維持する。
変更はMML出力周辺に限定し、大規模な書き換えはしない。

段階的に進める。

1. イベント抽出とWriterを分離し、同じタイミングのまま `@`・octave・音長の重複とコメント配置を整理する。
2. 量子化と `%tick` フォールバックを追加する。
3. gate検出と微小なピッチ変動の統合を追加する。

中間データには音高、音色ID、論理的な開始・長さ、gate長、再発音の有無、
元のサンプル区間への参照を持たせる。型の具体的な形は既存コードに合わせる。

## 6. テストと完了条件

既存の `docs/vgm_analyzer/vgm_mml.test.mjs` を拡張し、抽出・量子化・Writerを確認する。

1. 同じ8分音符の列が `l8` で簡潔になる。
2. octaveをまたいだ音程が維持され、不要な指定がない。
3. 安定した短いKEY OFF gapの列をgateとして表せる。
4. 長い休符、不規則な空白、判断できない終端が消えない。
5. 同一音色は重複せず、途中の変更は残る。
6. 付点・タイの長さが正しく、明示的な再発音を消さない。
7. 微小なピッチ変動をまとめても、半音境界や再KEY ONを誤って統合しない。
8. 許容誤差の内外で量子化と `%tick` が切り替わる。連符・装飾音を強制的に丸めない。
9. 複数CHの時間原点が揃い、長い列でも丸め誤差が累積しない。
10. 本文から詳細情報を追え、元のサンプル位置と未変換要素が失われない。
11. `q` の切り替え、`q100` への復帰、タイ全体へのgate適用が定義通りになる。

文字列が短いだけでなく、中間イベントの音程・時刻・gateを検証する。
元の音程と大まかなリズムを維持し、推測できない区間を明示して残せたことを完了条件とする。

実装後は、変更ファイル、変換経路、量子化・gate・ピッチ統合の具体的な判定値、
確認結果、未対応ケースを簡潔に報告する。


## 実装したルール

- `vgm_mml.js` がサンプル単位の音符イベントを抽出し、`vgm_mml_music.js` の
  `quantizeNotes()` と `writeMml()` を順に呼ぶ。再生・画面側Note-ishは変更しない。
- 量子化は四分480tick、32分60tick。誤差が6tick以内かつ10ms以内の場合だけスナップ。
  その他は絶対時刻からtickへ換算する。極短音は0tickになる場合も元イベントを残す。
- gateは3連続区間以上、空白100ms以下、発音割合75%以上、発音間隔差5%以内、
  発音割合差3ポイント以内で適用。百分率へ丸め、誤差を詳細に記録する。
- 微小ピッチ変動は同じKEY区間・同じ音色・同じ最近傍半音で、最初の音高から20cent以内なら統合。
  時間長による判定は行わず、半音をまたぐ揺れや再KEY ONは残す。
- default lengthはCH内で3回以上使われる最頻の通常音価を一度設定。付点と2項までのタイに対応。
- 本文の音符をN1から数え、後続の詳細コメントに元の区間・量子化誤差・gate誤差を記録する。
- 元の非対応要素の警告、周波数・音色変更の詳細は維持。itch.ioの配布対象にも追加。

変換テストでは本文の簡潔さに加え、中間イベントのgate、音高、元イベント対応、
絶対時刻、フォールバックを確認する。外部ドライバの再生互換や実VGMの完全復元は保証しない。
