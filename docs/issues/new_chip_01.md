# YM2413 を追加するシミュレーション

## 方針

先に大きな interface を決めず、YM2413 を追加するときに変わるユーザー操作と実装箇所から境界を見つける。
OPN／OPM／OPLL の内部実装は独立させ、重複は許容する。
以前挙げた `extractInstruments` / `extractMidi` / `extractMML` / `extractOperator` / `toneOn` / `toneOff` は機能の列挙であり、採用済みの interface ではない。

以下は現行コードを確認した実装シミュレーション。YM2413 対応を実装済みという意味ではない。
初回は YM2413 単体、次に YM2413 + PSG の VGM を対象にする。旧 VGM 1.00 の解釈や第2チップ対応まで同時に広げない。

## 1. ファイルを開いて曲を再生する

ユーザーのファイル選択・プレイリスト・Play/Pause・シークの操作は変えない。
VGM コマンドを対応する音源へ送る既存の構造を使う。音色編集用の interface を再生経路に挟む必要はない。

| 実装箇所 | YM2413 を入れた場合の変更 |
| --- | --- |
| `src/ymfm_opl.h` / `.cpp` | `ymfm::ym2413` は既にある。新たなエミュレーションコアは不要 |
| `wasm/ym2203_wasm.cpp`、`scripts/build_ym2203_wasm.sh` を参考にする | YM2413 用ラッパーとビルドを追加。reset・レジスタ書き込み・PCM 生成を公開する |
| `web/ym2203.js`、`web/ym2203audioengine.js` 等を参考にする | YM2413 用 JS ラッパーと AudioEngine を追加。既存プレイヤーが要求する生成・リセット・破棄の契約を満たす |
| `web/ym2612vgm.js` の `parseHeader` / `step` / `playStep` | YM2413 クロック、0x51 の書き込みイベント、YM2413 target への配送を追加。現在は対応イベントがない |
| `web/vgmplayer.js` の target 構築 | `writeYm2413(register, value)` を持つ engine を parser へつなぐ |
| `docs/vgm_analyzer/vgm_analyzer.js` の音源判定・engine 作成 | YM2413 分岐とクロックを追加。既存の OPN 用 engine を誤選択させない |
| docs 配布物・パッケージスクリプト | JS/WASM とその依存ファイルを配布に含める |

コアの出力数を左右ステレオと決めつけない。`opll_registers` は旋律とリズムを別出力にしているため、ラッパー側で意味を確認してミックスする。
PSG を含む曲では PSG も生成し、同じ時間軸でミックスする。

再生開始だけでなく、停止・リセット・シーク後のレジスタ状態の復元、曲の切り替え時の音源破棄まで確認する。
この段階で未対応の解析・編集ボタンは無効にし、OPN の結果を表示して成功したように見せない。

## 2. 再生中のチャンネルを見る・ミュートする

ここで最初に OPN 前提へぶつかる。
`createChannelMonitorState()` は YM2203 なら3、それ以外は6チャンネルという構造。
YM2413 コアは9チャンネル・各2 Operator で、リズムモードもある。単にチャンネル数を9に変更しても解決しない。

- モニターの外側のタブや表示領域は維持する。
- YM2413 のレジスタ保持・表示・ミュート処理は専用実装にする。
- OPN 用の Operator フィールドへ YM2413 の値を無理に詰めない。
- 旋律／リズム切り替えで表示対象とミュート対象が変わることを扱う。
- 表示用の原レジスタ状態と、ミュートのため加工する再生書き込みを分ける。解除後に正しい状態を復元できるようにする。

最初の境界候補は「再生中の音源状態を表示・操作する部分」。
既存の PSG / RF5C164 の monitor 分離を参考に、YM2413 の表示を追加してから必要な呼び出し口を決める。
まだ全系統の monitor interface を一括定義しない。

## 3. 曲から音色を選ぶ

一覧から選択する操作は維持できるが、一覧を作る処理と選択した音色の中身は変わる。
現行 `extractTfiPatchesFromVgm` や Playground の `createVgmPresetFiles` は OPN のレジスタと TFI を前提にしている。
YM2413 の抽出をそこへ TFI として追加しない。

YM2413 では次を区別して記録する。

- 内蔵音色を番号で選んだもの。
- 共有のユーザー音色レジスタから取得した音色。使用時点の値をコピーする。
- リズムモードの音。旋律用の音色と同じ扱いにするかは別途決める。

同じユーザー音色番号でも、途中でレジスタが変われば異なる音色になり得る。
キーオン時だけを調べると、発音中の音色書き換えを取りこぼす。最初の抽出で扱う範囲を明記する。
音色の重複判定は YM2413 側が行い、一覧側はその内部構造を解釈しない。

## 4. 選んだ音色を編集して試奏する

「選ぶ → パラメータを変更する → 鍵盤を押す／離す」という操作は同じ。
差し替わるのは、パラメータの編集画面と音源へ変更を適用する部分。

現行 `docs/vgm_analyzer/tfi_info.js` は `playground_tfi_editor.js` を使い、TFI と MegaSynth を前提にしている。
この TFI エディタを万能化するより、YM2413 専用の編集・試奏部分を作る。

| 外側に残すもの | YM2413 側で実装するもの |
| --- | --- |
| 一覧・選択・タブ切り替え | 選択データの解釈 |
| 編集領域の配置 | 2 Operator の編集項目と値の検証 |
| 鍵盤の押下・解放、フォーカス操作 | 音程のレジスタ化、キーオン／オフ |
| 試奏音量の操作 | 試奏用音源への音量適用 |
| 曲の切り替え、画面を閉じる操作 | 試奏停止・専用音源の破棄 |

内蔵音色を編集するなら、ユーザー音色へのコピーとして扱う方針が必要。
試奏は曲再生と別の音源で行い、共有ユーザー音色の変更が曲へ影響しないようにする。
最初は単音試奏でよい。複数の異なるユーザー音色を同時に鳴らす仕組みまで広げない。

ここが次の境界候補。「選択した音色を編集・試奏する部分」を独立させる。
既存 OPN エディタと YM2413 エディタを実際に並べてから、ホストとの最低限の接続方法を決める。
TFI 専用タブ名を維持するか、音色タブの中で形式別に表示するかも、この段階で変更する。

## 5. 音色を保存する

ダウンロードや virtual file に置く操作はそのまま使える。
ファイルの内容・拡張子・読み戻しは音源固有にする。YM2413 を `.tfi` として保存しない。

初期の再生対応に保存形式の実装を必須としない。編集に進む時点で、まず何を失わず保存するかと交換先を決める。
内蔵音色番号を保存する場合は、どのチップの音色かも必要になる。

## 6. Note-ish を見る・MIDI / MML を保存する

`vgm_notes.js` の `extractOpnNotes` と `midiChipKind` は既存音源に依存する。
時間軸の表示を作り直す前に、YM2413 専用の音符解析結果を既存表示へ渡せるかを確認する。
周波数・キーオン・リズムの解釈は YM2413 側へ置く。

- Note-ish：旋律の音符表示から追加する。リズムや発音中の音程変化をどう表すかは明示する。
- MIDI：既存の SMF 書き出しを使えるか確認し、YM2413 の音符解析をつなぐ。併用 PSG のトラックを落とさない。
- MML：現行出力先の音源前提を確認する。OPN 用音色定義へ無理に変換せず、対応する方言を選ぶまでは無効にする。

これらは再生・試奏ができてから別々に追加できる。全機能を一つの interface に実装し終えるまで待つ必要はない。

## 最初の実装単位

まず「YM2413 の VGM が再生できる」を小さな変更単位にする。

1. WASM / JS ラッパーを追加し、既知のレジスタ列で PCM が生成できることを確認する。
2. parser のヘッダー・書き込みイベント・target 配送を追加する。
3. AudioEngine と VgmPlayer をつなぐ。
4. Analyzer の音源選択と未対応機能の表示を整える。
5. YM2413 単体と PSG 併用で再生・停止・シーク・ファイル切り替えを確認する。

確認は、短い合成 VGM による書き込み順序と wait のテスト、PCM 生成、既存 OPN の回帰確認、ブラウザでの実際の再生操作に分ける。
その後、monitor → 音色一覧 → 編集・試奏 → 保存 → Note-ish / export の順に進める。
各段階で必要になった境界だけを切る。既存 OPN の全面移動や共通 Preset 型の設計を先行させない。

## 最初の実装（YM2413 再生）

- YM2413 の WASM / JS / AudioEngine、VGM 0x51 の配送を追加した。
- Analyzer は YM2413 単体と Sega PSG 併用の再生に対応する。
- YM2413 選択時は Parsed Output を表示し、Operator / Note-ish / TFI / Samples と音色・MIDI・MML・snapshot export を無効にする。画面に `Support coming soon.` を表示する。
- 今回はチップ単位の解析選択 UI がないため、YM2413 + PSG でも解析タブ全体を無効にする。PSG だけの部分 export は今後の課題。
- YM2413 の第2チップ・別モデル・他 FM チップ等との混在は、再生開始時に未対応として明示する。
- 境界は Analyzer 内の `updateChipSupport()` に留めた。汎用 interface はまだ作らない。
- ビルドは `sh scripts/build_ym2413_wasm.sh`。ランタイム同期・Analyzer 配布スクリプトにも追加した。

## YM2151 の再生対応

YM2151 の WASM / JS / AudioEngine と VGM 0x54、ヘッダー 0x30 の読み取りを追加。
Analyzer は YM2151 単体と Sega PSG 併用を再生し、Parsed Output から情報を確認できる。
Operator / Note-ish / 音色編集 / export は準備中として無効化する。
8チャンネルの左右定位、タイマー、リセット、シーク、コマンド集計をテストした。
YM2164・2基目・DAC ストリーム・Sega PCM 等との複合再生は今回の対象外。
ビルド：`sh scripts/build_ym2151_wasm.sh`。実ブラウザでの実曲試聴は未確認。
