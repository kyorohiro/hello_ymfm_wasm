# AY-3-8910 対応の実装方針

## 目的

MAME の AY-3-8910 実装を移植し、VGM Analyzer で AY 系 PSG を再生・表示できるようにする。
最終的には YM2413（OPLL）との同時再生を追加し、両音源を使用する MSX-MUSIC の VGM を再現する。

この文書は実装計画。AY 音源の移植・WASM 化・Analyzer への接続は未実施。

## 前提と対応範囲

- AY-3-8910 と YM2413 は別音源。PSG と OPLL を使用する曲は両方の実装が必要。
- すべての MSX 曲が両方を使用するわけではない。ヘッダーに応じて AY 単体、OPLL 単体、併用を扱う。
- SCC や MSX-AUDIO など、他の音源を使用する曲まで今回の組み合わせだけで対応できるとはしない。
- AY-3-8910 と Sega PSG（SN76489 系）は別実装にする。Sega PSG のラッパー構成は参考にできるが、音源ロジックの置換で済ませない。
- 既存の `src/ymfm_ssg.*` は Yamaha SSG の実装。存在だけを根拠に AY の厳密な互換性を保証しない。
- AY と YM2149 の挙動・音量特性を混同しない。型を区別できる API とし、未対応型は明示する。

初期対応は AY-3-8910 1基の音声再生。YM2149 は次段階で差分を検証して追加する。
複数チップ、派生型、S98 対応は別の完了条件を設ける。

## 移植元と既存の手本

MAME は音源デバイスとして AY 系を実装している。ただし、独立ライブラリとしてそのままビルドできる形ではなく、MAME のデバイス／ストリーム基盤からの分離が必要。

- [MAME ay8910.cpp](https://github.com/mamedev/mame/blob/master/src/devices/sound/ay8910.cpp)
- [MAME ay8910.h](https://github.com/mamedev/mame/blob/master/src/devices/sound/ay8910.h)

確認した upstream ヘッダーのライセンス表記は `BSD-3-Clause`、著作権者表記は `Couriersud`。
取り込み時にコミット SHA を固定し、採用する両ファイルと追加依存の表記を確認・保存する。
`master` の URL だけで移植元を管理しない。

このリポジトリの手本：

- [RF5C164 移植メモ](../../third_party/mame-rf5c164/README.md)
- [RF5C164 移植コード](../../third_party/mame-rf5c164/rf5c164.cpp)
- [元実装との比較スクリプト](../../scripts/verify_rf5c164_reference.py)
- [WASM ラッパー](../../wasm/rf5c164_wasm.cpp)
- [ビルドスクリプト](../../scripts/build_rf5c164_wasm.sh)
- [JavaScript ラッパー](../../web/rf5c164.js)

RF5C164 と同じく、元ソースを保存し、変更点を記録し、元のレジスタ処理・音声生成との比較を行う。
切り出し規模が RF5C164 と同程度かどうかは依存調査後に判断する。


ファイル名と API は暫定。YM2413 との複合エンジンは別途設け、AY 単体エンジンへ OPLL 固有処理を混在させない。

## 音源コアの切り出し

### 保持する機能

- 3ch のトーン周期・位相・カウンター。
- 共有ノイズ生成器と、各チャンネルのトーン／ノイズ混合。
- 固定音量、共有エンベロープ、形状レジスタ書き込み時の再始動。
- レジスタの有効ビット、周期ゼロなどの境界条件、リセット状態。
- AY／YM の違いを含む、採用する型の音量・出力特性。

### 分離する機能

- `device_t`、`device_sound_interface`、`sound_stream` などの MAME 基盤。
- デバイス登録、機種設定、MAME の保存状態管理、外部 I/O コールバック。
- ホストの音声時刻管理。VGM 側から与えた時間だけコアを進める。

音声 VGM 再生では MSX の CPU やキーボード／ジョイスティックの I/O を再現しない。
ただし I/O 関連の書き込みを無条件に捨てず、方向ビットを含むレジスタ状態を保持し、音源部分へ誤作用させない。

### ホスト API 案

```cpp
reset();
write(uint8_t reg, uint8_t value);
generate(float *left, float *right, uint32_t frames);
sample_rate();
```

生成時にチップ型、入力クロック、出力サンプルレートを指定する。
必要ならモニター用にレジスタ読み取りとチャンネル別出力を追加する。

AY の出力を安易に Sega PSG と同じ音量テーブルや左右定位にしない。
MAME の出力モデル、抵抗負荷、正規化、ミックス方法を確認して採用条件を文書化する。
初期の左右出力は同じモノラル信号とし、音量とクリッピングを検証する。
リサンプル方式は矩形波・ノイズ・高速音量書き込みへの影響を比較して決める。

## VGM / Player への接続

対象は `web/ym2612vgm.js`、`web/vgmplayer.js` と対応する `docs/js/`。
既存クラス名が YM2612 でも、すでに複数音源を扱うため接続箇所を確認して追加する。

1. AY クロック、チップ型、関連フラグをヘッダーから読み取る。
2. AY のレジスタ書き込みコマンドをイベント化する。
3. `playStep()` から AY の書き込み先へ配送する。
4. `VgmPlayer` の待ち時間に従って生成し、レジスタ書き込みとの順序を維持する。
5. リセット、停止、ループ、シーク、ミュートを既存経路へ接続する。

[VGM 仕様](https://vgmrips.net/wiki/VGM_Specification)で、ヘッダーのバージョン／長さ条件、書き込み命令、2基目の指定、データストリームの配送を実装時に照合する。
今回の調査では仕様ページがアクセス制限画面になったため、数値定義を確認済みとして固定しない。
未対応の型・2基目・併用音源は警告し、1基目への誤配送や「完全対応」の表示を避ける。

`web/s98_file.js` は現状の対応デバイスが限定されている。
AY の VGM 対応だけで S98 対応済みとはせず、デバイス番号とクロック変換を別途検証する。

## Analyzer と YM2413 併用

- `docs/vgm_analyzer/vgm_analyzer.js` のチップ判定、エンジン生成、音源切り替えに追加。
- AY の A/B/C、トーン／ノイズ有効状態、固定音量／エンベロープ使用状態を表示。
- チャンネルミュートはコアの位相やエンベロープ進行を止めない。
- Note-ish の音程表示はトーン周期に対応させる。ノイズを通常の音程として表示しない。
- MIDI/MML は AY 再生対応と別扱い。未実装の出力を有効にしない。
- YM2413 は既存 `src/ymfm_opl.*` を WASM 化し、AY と共通の時間軸・出力レートで混合する。
- 同じチップ構成でも曲ごとにクロックが違うケースを扱う。
- 音源リセット、プレイリスト次曲、曲ループ、シーク後も両音源を同期させる。

## 検証方法

### 単体と移植一致

- 固定した MAME 元実装に同じ時刻・同じ書き込み列を与えて比較する。
- トーン各ch、ノイズ、全エンベロープ形状、固定音量、ミキサーの組み合わせを検証する。
- 周期ゼロ／最小／最大、再生途中の周期変更、同値の形状再書き込み、リセットを含める。
- 同じ出力条件でコア出力を比較し、リサンプルや正規化の差は分けて評価する。
- 512／2048／不規則な生成分割で、同じレジスタ時刻列から同じ連続波形が得られることを確認する。
- AY と YM2149 は別の期待値を用意する。移植元一致は実機全体との完全一致を意味しない。

### VGM 統合

- 最小 VGM で AY 単体の書き込み・待ち・終端・ループを検証する。
- OPLL＋AY の両方を使用する、出典を記録した実曲で同時再生を確認する。
- AY のみ／OPLL のみをミュートして、音源の欠落や誤配送がないことを確認する。
- 連続再生とシーク後の状態、プレイリスト曲切り替え、異なるクロックを検証する。
- 未対応型、短いヘッダー、不正コマンド、2基目指定を検証する。

### 性能

軽いはずという推測だけで判断せず、イベント数、生成サンプル数、生成呼び出し回数、処理時間を測る。
長時間タスクが出た場合は解析・音源生成・モニター・コピーの内訳を確認する。
既存の 2048 サンプル設定やキュー閾値を、根拠なく変更しない。
「2048 以外では VF にノイズが出る」という因果は、この会話では未検証。

## 実装順序と完了条件

1. **移植元固定と依存調査**：SHA、ライセンス、切り出す範囲、出力条件が記録されている。
2. **AY コア**：単体ビルドと MAME 元実装との比較が通る。
3. **WASM / JS**：生成・書き込み・リセット・破棄・分割生成の検証が通る。
4. **AY 単体 VGM**：Analyzer で再生・表示・ミュート・ループ・シークできる。
5. **YM2149 差分**：型に応じた音量・エンベロープ・クロック挙動を検証する。
6. **YM2413 併用**：PSG と OPLL を使う VGM の両音源が同期して再生される。
7. **配布**：ビルド、配布スクリプト、README、ライセンス同梱、対応範囲の表示を更新する。

特に `scripts/package_itch_vgm_analyzer.sh` は同梱ファイルの明示リストを持つため、追加が必要。
他の配布物についても、その音源を含めるものだけ関連ファイルとライセンスを追加する。

## 未確定事項

- 採用する MAME コミットと、AY 固有処理の追加依存。
- 初期出力モデル、リサンプル方式、音量基準。
- 検証対象の MSX VGM が指定する AY 型と関連フラグ。
- YM2149、2基目、データストリーム、S98 の対応優先順位。
- 比較用の実曲と、参照音源の取得・再配布条件。

実装可能性はある。主な作業は新規に発振器を考案することより、MAME 基盤からの分離と、時間・出力条件を保った統合・検証になる。
