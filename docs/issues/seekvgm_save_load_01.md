# VGMシーク高速化：Sound Chip Save / Load

全体の対応状況：[機能一覧](../feature-status.md)。この文書は本機能の詳細・作業記録。

## 目的と現状

少し戻すだけでも先頭からの再演算を待つ問題を改善する。
従来の `docs/vgm_analyzer/seek_playback.js` は `player.reset()` 後、目的位置まで無音で音声を生成していた。
そのため、3分地点から2分55秒へ戻る場合も、先頭から2分55秒ぶんの演算が必要だった。

この文書は設計・対応管理用。Genesis構成およびYM2203・YM2608・YM2610／YM2610Bのチェックポイントによる高速シークを実装済み。OPM（YM2151）とSega PSG・Sega PCM・OKIM6258の併用にも対応済み。

## 方針

アプリの中心であるOPN系とOPM（YM2151）を優先する。
特にGenesisを最初の実用対象とし、YM2612 + Sega PSGに加えて32X PWM・RF5C164を対象に含める。
OPLL / OPL系やGame Boyなどは、その後の拡張とする。

各Sound Chipの保存・復元機能を土台に、音声エンジンとVGMプレイヤーを含むチェックポイントを保存する。
シーク時は目的位置以前の最寄りのチェックポイントを復元し、残りの区間だけ無音で進める。

```text
通常再生中：0秒 → 5秒で保存 → 10秒で保存 → 15秒で保存 …
13秒へ移動：10秒の状態を復元 → 3秒ぶん無音で進める → 再生
```

- 保存間隔はまず5秒を候補とし、状態サイズと待ち時間を測って決める。
- 一度通った場所への移動から高速化する。未到達の位置は既存方式で進め、途中にも保存する。
- 全曲の先行生成は初期実装では必須にしない。
- 曲で使う全チップ・全インスタンスが復元可能な場合だけ有効にする。
- 未対応チップを含む曲は既存の先頭からの再演算へフォールバックする。
- レジスタのスナップショットや音色Exportとは別の機能。位相やエンベロープの途中状態も必要。

## 保存する状態

| 層 | 対象 |
|---|---|
| Sound Chipコア | レジスタ、位相、エンベロープ、LFO、ノイズ生成器、タイマー、ADPCMデコーダー、再生アドレスなど |
| WASMインターフェース | コア外で管理するタイマー／時刻、RAM、バンク、外部メモリーなど |
| 音声エンジン | リサンプラーの位相・端数・履歴、未消費サンプル、全チップの状態 |
| VGMパーサー | コマンド位置、wait残量、PCMデータバンク／読み出し位置、ストリーム状態、ループ関連状態 |
| VGMプレイヤー | `waitAccumulator`、処理済み時間、先読みキューと消費位置など |
| Analyzer | レジスタ表示・モニターなど、シーク後の表示を再同期するための状態 |

`web/vgmplayer.js` は音声を先読みするため、コマンド位置と実際に聞こえる位置が一致するとは限らない。
キューを含めて復元するか、安全な保存境界を設けるかを決め、欠落・重複が起きないようにする。
Web Audioへ既に送った旧音声もシーク時に破棄・再同期する。

最適化方針として、不変の曲データやROMは共有参照と識別情報で扱いたい。初回のOPN実装では正確性を優先してROMもコピーする（後述）。
書き換え可能なRAMは保存対象とし、保存後の変更が過去のチェックポイントに混入しないようコピーする。
ミュートやマスター音量などのユーザー設定は、復元時に現在の設定を再適用する。

## Genesis周辺3音源の調査結果

調査時点では既存Save / Load APIがなかったため、以下の状態を保存するAPIを追加した。
実WASMでリセット・RAM変更後の復元音声が完全一致することを検証済み。

### Sega PSG

`src/segapsg.h` の `SegaPSG` に状態がまとまっている。
3トーンのperiod / counter / output / volume、ノイズLFSR・制御・音量・カウンター・出力、
書き込みラッチ、クロック端数 `m_clock_accumulator` を保存する。
クロックとサンプルレートの整合性も確認する。大きな外部メモリーはなく、最初に対応する候補。
レジスタ再送ではノイズ系列やトーン位相を復元できないため、明示的な状態APIを追加する。

### 32X PWM

`web/genesisaudioengine.js` の `SimplePwm` は、VGM書き込み値を次の書き込みまで保持する近似実装。
現在の保存対象は `cycle`、`control`、`left`、`right`。未書き込みの `null` も保持する。
`muted` はユーザー設定として復元後に現在値を適用する。
FIFOやハードウェアタイマーは現実装に存在しないため、それらの保存実装は今回不要。
JS内で対応できる見込み。ただしVGM側の書き込み時刻・ストリーム位置の復元も必要。
Save / LoadによってPWMのエミュレーション精度が変わるわけではない。

### RF5C164

`third_party/mame-rf5c164/rf5c164.h` の採用コアでは、8チャンネル、64 KiB RAM、
チャンネル／RAMバンク、全体enable、出力レート／クロック、リサンプリング位相 `phase_`、
直前出力 `left_` / `right_` が状態の対象になる。
各チャンネルの `addr` は小数部を含む再生位置なので丸ごと保存する。
既存の `load()` はPCMデータをRAMへ書く機能であり、状態復元APIではない。
RAMを含めた保存APIをC++・WASM・JSへ追加する。

RAMだけでも1チェックポイント64 KiB。5秒間隔で10分ぶん約120個なら約7.5 MiBとなり、
他の状態やコピーのオーバーヘッドも加わる。まず完全コピーで正しさを検証し、容量上限を設ける。
現在の `reset()` はRAMを保持するため、リセットやレジスタ再送でSave / Loadを代用しない。

## API案とキャッシュ管理

Genesis向けに実装した内部API。状態は同一インスタンス／同一曲専用の不透明なトークンで、JSON保存や別インスタンスへの移植には対応しない。

```js
const checkpoint = player.saveState(); // parser + engine + chips + queue
player.loadState(checkpoint);
// 目的位置までの差分だけ無音で進める
```

- 各チップ／エンジンは保存対応の可否を明示し、プレイヤー側で全インスタンスを確認する。
- 当面は同一曲・同一実行環境内のメモリー上のキャッシュ用途に限定する。永続ファイル互換性は別課題。
- 形式バージョン、チップ種別とインスタンス番号、クロック、出力サンプルレート、曲／ROM識別情報を検証する。
- 曲・ROM・クロック・出力レート・コア構成の変更時にキャッシュを無効化する。
- 復元前に全体を検証し、失敗時に一部チップだけが復元された状態で再生しない。
- キャッシュ容量に上限を設ける。最近の再生位置付近を優先するなど、保持方針は測定後に決める。
- 保存は全チップとパーサーを同じ論理時刻で停止した境界で行い、途中更新を取り込まない。
- WASMメモリー全体の単純コピーやC++オブジェクトの丸ごとコピーは前提にしない。ポインターやJS側状態を含む明示的な保存範囲を定義する。

- OKIM6258追加構成・保存APIを持たない旧WASMは従来シークへフォールバック。
- 新しい曲・エンジンではキャッシュを作り直す。初めて進む位置、保存が容量制限で破棄された区間、最初の約5秒は先頭または既存保存地点からの再演算が必要。

## OPN系の追加実装（2026-09-29）

対象はAnalyzerで再生するYM2203・YM2608・YM2610／YM2610B。既存のYM2612対応と合わせて、AnalyzerのOPN系をカバーする。
YM3438・YMF288は引き続きライブラリー側の拡張候補。YM2151はOPMとして次段階に残す。

### 状態保存と復元

- 3つのWASMラッパーへSave / Loadを追加。YM2610／YM2610Bは同じラッパーのvariantで対応する。
- `wasm/opn_state.h` に、ymfmコア・タイマー残量・IRQ・ミュートマスク・可変長メモリーの保存処理を共通化。
- 復元前に全メモリー領域の長さ・上限・総サイズを検証してコピーを準備する。切り詰められた状態や過大な領域長を拒否する。
- YM2608は8 KiBリズムROMと2 MiB ADPCM-B RAMも保存。YM2610系はADPCM-A/BのROM内容とサイズを保存し、曲途中のデータブロック更新も巻き戻せる。
- 今回は正確性を優先し、ROMもチェックポイントごとにコピーする。共有・差分保存は未実装。RAM／ROMが大きい曲では32 MiB上限により保持できるチェックポイント数が減る。単一状態が上限を超える曲は従来シークになる。
- 各エンジンのリサンプリング端数と直前の左右サンプルを保存する。アップサンプリングでチップを進めないフレームも再現する。
- YM2608の `save_restore` では、復元時に分周設定から派生値を再構築する処理を補完。
- YM2610の `save_restore` では、出力を保持している区間を再現するため `m_last_fm.data` の保存を補完。
- チップ側のJS APIはGenesisと同じ、同一インスタンス専用の不透明な状態トークン。別インスタンス／別variantへ持ち込めない。

### Analyzerへの接続

- OPN系でも約5秒間隔の自動保存を有効化。同一曲のPlay／シークでパーサーを作り直さず、キャッシュを保持する。
- FM／SSGモニター、周波数ラッチを音声状態と一緒に復元する。
- YM2608の外部リズムROM差し替え時はキャッシュを明示的に破棄する。エンジンにもROM世代番号を持たせ、古いROMの状態復元を拒否する。
- ミュート・音量・サンプルレートの異なる状態は復元しない。OKIM6258追加構成や旧WASMは従来シークへ戻る。
- `docs/js` と配布用 `docs/generated` のYM2203・YM2608・YM2610Bを更新。

### autotest

`web/opn_state.test.mjs` を追加（19件）。次を実WASMで確認する。

- FM、SSG、リズム、ADPCM-A/B、YM2610B追加FMチャンネルの発音途中の状態を保存。保存自体が音を変えず、リセット／メモリー変更後も復元PCMが完全一致する。
- YM2203／YM2608の分周設定、SSGノイズ・エンベロープ、タイマー状態、書き込みポートのラッチを復元。

## OPM対応（2026-09-29）

YM2151単体、およびSega PSG・Sega PCM・OKIM6258を併用するYM2151エンジンに
チェックポイントによる高速シークを追加した。同じ曲のPlay／seekでキャッシュを保持する。
5秒間隔・120個／32 MiBの既存上限を共通利用し、保存地点から目的位置までの差分だけ生成する。

### 保存範囲

- YM2151：ymfmコア、WASM側のタイマー残量・IRQ・ミュートマスク。
  ランダムLFOの波形テーブルは実行中に書き換わるが、既存の`save_restore`では保存されていなかった。
  復元音声一致テストで差を検出し、`src/ymfm_opm.cpp`でこのテーブルも保存するよう補完した。
- Sega PCM：16音源の再生アドレス・小数部・ループ・バンク・音量・制御、
  クロック端数、直前の左右出力、ミュート、ROM内容とサイズ。
  ROMを含めてコピーするため、大きいROMでは容量上限により保存できる区間が短くなる。
- OKIM6258：ADPCMデコーダー、FIFOと読み出し位置、半バイト途中の状態、
  クロック／分周・パン・出力位相・直前サンプル。
- YM2151エンジン：全併用チップとリサンプラー端数・保持サンプル。
  ミュート・音量などが変わった場合は古いチェックポイントを利用しない。
- Analyzer：OPMレジスタ・キー状態・AMD／PMD・変更表示、ノート履歴・ID、PSG／PCM表示。

### 検証

`web/opm_state.test.mjs`に実WASMを使う自動テストを追加。
自作fixtureでYM2151単体、YM2151＋Sega PCM、YM2151＋Sega PCM＋PSG、
YM2151＋OKIM6258を検証する。

- リセット／ROM破棄後の復元音声が左右とも完全一致し、繰り返し復元できる。
- チェックポイント経由の巻き戻しが先頭からの再生と完全一致し、再演算量が減る。
- ランダムLFO・ノイズ・タイマー・書き込みアドレスラッチと、OKIM6258のFIFO途中を復元する。
- 別インスタンス・設定変更・不正なROM長の状態を拒否する。
- Analyzer接続で同一曲のキャッシュ保持、曲変更時の破棄、OPM表示復元を検証する。
