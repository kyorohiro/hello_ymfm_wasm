# YM2413（OPLL）追加と VGM 1.00 対応の実装方針

## 目的と範囲

既存の ymfm YM2413 コアをブラウザーへ接続し、YM2413 単体と Sega PSG（SN76489 系）併用の VGM を Analyzer で再生する。
Master System / Mark III の FM 音源対応を先に進め、その後 [AY-3-8910 対応](ay8910_01.md)と組み合わせて MSX-MUSIC へ広げる。

この文書は実装計画。WASM ラッパーや Player / Analyzer への追加は未実施。
ここでの「VGM 1.0」はファイルバージョン **1.00（`0x00000100`）** を指す。
YM2413 を追加するだけで VGM 1.00 全体の完全対応とはしない。旧ヘッダーの解釈と PSG の既存対応も検証する。

初期対象は YM2413 1基、Sega PSG 1基、および両者の併用。AY / YM2149、VRC7 などの派生型、2基目、S98、MIDI/MML 出力は別段階とする。
後の VGM バージョンで記録された同じ音源についても、既存パーサーの対応範囲内で再生する。

## 既存資産と不足箇所

- [src/ymfm_opl.h](../../src/ymfm_opl.h) / `.cpp` に `ymfm::ym2413` と内蔵音色データがある。新たな外部音源コアの移植は不要。
- [examples/vgmrender/vgmrender.cpp](../../examples/vgmrender/vgmrender.cpp) に YM2413 の生成と `0x51` 書き込みの手本がある。ただし旧形式互換性の正解として無条件に扱わない。
- [web/ym2612vgm.js](../../web/ym2612vgm.js) は複数音源の共通パーサーだが、現在 `ym2413Clock` の取得と `0x51` のイベント化がない。
- 同パーサーは 1.50 未満のデータ開始位置を `0x40` にしている一方、YM2612 クロックをバージョンによらず `0x2c` から読んでいる。旧形式の補正が必要。
- Sega PSG の生成・ミックスは既存コードを利用できるが、Game Gear ステレオ命令 `0x4f` の配送と左右制御を追加・検証する必要がある。
- [docs/vgm_analyzer/vgm_analyzer.js](../vgm_analyzer/vgm_analyzer.js) の音源判定、エンジン生成、モニター、曲切り替えにも追加が必要。

## VGM 仕様と互換性

参照資料：

- [VGM 仕様](https://vgmrips.net/wiki/VGM_Specification)
- [vgmrips の仕様テキスト（vgmspec171.txt）](https://github.com/vgmrips/vgmplay-legacy/blob/master/VGMPlay/vgmspec171.txt)

2026-09-12 の確認では Wiki 本文はアクセス制限になったため、公式リポジトリの仕様テキストを取得して確認した。
旧形式のクロック補正について検索結果の Wiki 記述とテキストには条件表現の違いがある。実装時は参照プレイヤーの処理と照合し、採用した資料・コミットを記録する。

| 項目 | 実装方針 |
| --- | --- |
| YM2413 クロック | `0x10` を取得。ただし旧形式の共有クロック用途を判定してから音源を選ぶ。 |
| YM2413 書き込み | `0x51 aa dd` をレジスタ `aa` への値 `dd` として配送する。 |
| 時間 | 待ち時間の単位は 44,100 Hz。AudioContext のレートへ端数を保持して変換する。 |
| データ開始 | 1.50 未満は `0x40`。以降は `0x34` の相対オフセットとヘッダー長を検証する。 |
| PSG 旧形式既定値 | 1.01 以下ではノイズ帰還 `0x0009`、シフト幅 16 を使用する。 |
| PSG ステレオ | `0x4f dd` を Game Gear の左右マスクとして扱い、通常の `0x50 dd` と区別する。 |
| ループ・終端 | 相対ループ位置、待ち命令、`0x66` を既存再生経路で扱う。範囲外・切れた命令は明示的に失敗させる。 |

1.01 以下では、`0x10` が YM2612 / YM2151 のクロックとして使われた形式もある。
値が非ゼロという理由だけで YM2413 を生成せず、命令列と参照実装を照合して補正規則を決める。
未対応の YM2151 などを検出した場合は警告する。予約領域を新バージョンの有効フィールドとして解釈しない。

「YM2413＋PSG 対応」と「VGM 1.00 互換性検証済み」は分けて記録し、後者は旧形式の検証完了後に表示する。

## ファイル構成と音声 API

```text
wasm/ym2413_wasm.cpp
scripts/build_ym2413_wasm.sh
web/ym2413.js
web/ym2413audioengine.js
docs/js/ym2413.js
docs/js/ym2413audioengine.js
docs/generated/ym2413_wasm.js
docs/generated/ym2413_wasm.wasm
```

既存の YM2203 などのラッパーに合わせ、生成・破棄・リセット・レジスタ書き込み・サンプルレート取得・音声生成を提供する。
YM2413 の入力クロックを生成時に指定し、内部レートはコアの `sample_rate(clock)` から取得する。
OPLL の出力バスの意味とスケールを確認してモノラル信号へ合成し、左右へ同じ信号を渡す。出力バスを安易に左右チャンネルと解釈しない。

`ym2413audioengine.js` は YM2413 と任意の Sega PSG を既存 Player の API に接続する。
両音源を同じ出力レート・時間軸へ変換し、書き込み境界とリサンプラーの端数を保持する。
PSG がない曲も再生でき、異なるクロックの曲へ切り替える際は必要なエンジンを作り直す。
音量基準とクリッピングを確認し、ミュート中も音源状態と時間を進める。

## Player / Analyzer への接続

1. パーサーに `ym2413Clock` と `ym2413-write` イベントを追加。命令長走査、ログ、事前解析も同時に対応する。
2. `playStep()` から YM2413 書き込みをエンジンへ配送する。PSG ステレオ用のイベント・配送先も用意する。
3. `VgmPlayer` の生成、停止、リセット、ループ、シークを通して状態と時間を一致させる。
4. Analyzer に音源判定、クロック表示、OPLL エンジン生成、イベント表示を追加する。
5. 9ch メロディーと、リズムモード時の 6ch＋打楽器を区別して表示する。内蔵音色番号、ユーザー音色、キー状態、音量を監視する。
6. 音源単位のミュートを先に接続し、ch / 打楽器単位のミュートは出力を分離できる方法を確認して追加する。キーオフ書き込みで代用しない。
7. Note-ish の音程は OPLL の F-number / block / クロックで計算する。打楽器を通常の音階として表示しない。未対応の MIDI/MML 出力は無効にする。

AY との併用は AY 側のコア・型判定が完成してから追加する。今回の Sega PSG 接続だけで MSX の PSG が鳴るとはしない。

## 検証と完了条件

### 1. WASM / JS

- 内蔵音色、ユーザー音色変更、キーオン・オフ、9ch、リズムモード切り替えを確認する。
- 同じレジスタ列の native ymfm 出力と、リサンプル前の WASM 出力を比較する。
- 512 / 2048 / 不規則な生成分割で波形が一致する。リセットの再現性と生成・破棄を確認する。

### 2. VGM 再生

- 最小 fixture で OPLL 単体、PSG 単体、併用、ステレオマスク、待ち、終端、ループを検証する。
- 1.00 / 1.01 / 1.10 / 1.50 以降のヘッダー境界、旧共有クロック、短いファイル、不正命令を検証する。
- 出典と使用音源を記録した実曲で参照プレイヤーと比較する。OPLL と PSG を別々にミュートして両音源の配送を確認する。
- 連続再生とシーク後、曲切り替え、クロック変更で同期と状態復元を確認する。
- 未対応の派生型・2基目・音源併用を黙って1基目へ配送しない。

### 3. Analyzer / 配布

- 音源表示、音色・リズム表示、ミュート、ループ、シークを確認する。
- 既存 YM2612 / YM2203 / YM2608 / YM2610 / PSG 再生の関連回帰チェックを通す。
- `web/` と `docs/js/` を同期し、ビルドと `scripts/package_itch_vgm_analyzer.sh` の同梱リスト、対応表、ライセンス同梱を更新する。
- AY 計画とは独立して「YM2413 単体＋Sega PSG 併用」を完了できる構成にする。

## 未確定事項

- 旧共有クロックの補正規則と、比較に用いる参照プレイヤーの固定コミット。
- OPLL 出力のミックス係数、リサンプル方式、ch / 打楽器単位のミュート方法。
- 比較用実曲の入手元と再配布条件。
- AY 併用、派生型、2基目、S98、MIDI/MML の優先順位。
