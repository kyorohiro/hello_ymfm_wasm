# PC Engine CD-ROM² audio

Select **PC Engine CD-ROM²** in Playground to use `pce` (HuC6280), `adpcm`
(MSM5205) and `cdda` together. The starter and `pce-cd-three-sources.js` generate
their own original audio; no disc, BIOS or sample ROM is needed. Browser and
experimental Native backends support Main and Worker execution.

Mixer exposes independent `huc6280`, `msm5205` and `cdda` inputs. Volume,
balance, Mute and Solo use the existing Mixer. Muting keeps playback advancing.
Opening a panel or reading state never writes audio parameters. All three
sources use the selected backend's existing output frame clock.

## Source tabs

PC Engine CD-ROM² mode shows **HuC6280 PSG**, **MSM5205 ADPCM** and **CD-DA**
next to Code, including before Run. HuC6280 retains its voice editor and audition.
The other two tabs show hardware details and read-only playback snapshots: RAM
usage, rate and nibble position for ADPCM; track, position and PCM format for CD-DA.
Open a tab or press **Refresh** to update the snapshot. Inspecting a source never
initializes audio or changes playback/Mixer settings. There is no periodic polling.

## ADPCM samples

Import an uncompressed PCM16/float RIFF WAV into Virtual Files, then run:

```js
await adpcm.loadSample('/audio/voice.wav', {rate:12});
await adpcm.play();
log(await adpcm.getState());
await adpcm.stop();
await adpcm.play({loop:true});
```

`loadSample` also accepts `{sampleRate, channels:[Float32Array, ...]}`,
AudioBuffer, WAV bytes or Blob. It downmixes to mono, linearly resamples and
encodes four-bit OKI ADPCM. Encoding runs during preparation, never in the audio
callback. Non-WAV compressed inputs require an explicit `decodeAudio` callback
when using the helper directly or Main execution; decoder functions and abort
signals cannot be passed through Worker RPC. File paths refer to Virtual Files.

`rate` is a hardware register value **0..15**, not a frequency in Hz. The current
1,536,000 Hz clock gives `clock / (48 * (16 - rate))`: rate0 = 2,000 Hz,
rate12 = 8,000 Hz, rate14 = 16,000 Hz and rate15 = 32,000 Hz. `loadSample`
defaults to rate12; `play()` retains that prepared rate unless overridden.
This is the emulation baseline, not a measurement of a particular console.

The encoded sample is limited to **64 KiB / 131,072 nibbles**. At 8 kHz this is
about 16.38 seconds. Input PCM is checked before channel allocation, with a
128 MiB decoded-value limit. Oversized samples are rejected rather than silently
truncated. Select/trim a suitable region using the existing audio editor first.
The metadata reports original encoded `frames` and even `paddedFrames`; default
playback excludes an extra padding nibble.

For already encoded samples:

```js
await adpcm.loadMemory('/audio/drum.adpcm');
await adpcm.play({offset:1, length:999, rate:15, loop:false});
```

Data uses high nibble first. `offset` and `length` count **nibbles**, not bytes,
seconds or output frames. Odd starts and lengths are supported. Raw memory loads
default to rate15; pass the correct rate for the sample. `play` resets the ADPCM
predictor; a loop continues the predictor at its wrap point. Arbitrary encoded
samples can click at loop boundaries and may need editing or re-encoding.

`play`, `stop`, `reset` and `writeRegister(register,value)` accept an optional
absolute audio-clock `{at}` timestamp (`play` takes it in its options object).
Scheduled commands acknowledge queue admission, not completed playback. `stop`
cancels earlier queued playback commands; `reset` also resets decoder controls.
Both retain prepared RAM for replay. Playground Stop retires the endpoint and
cancels preparation, uploads and scheduled starts. A failed replacement preserves
the previously accepted source; a cancelled upload must be loaded again.

`getState()` reads the output-side source position in `positionNibbles`, playback
state, rate, clock, output frame and effective mix settings. Raw register writes
use the existing decoder register scheme (0..7, values 0..15); the first raw write
switches away from RAM playback. Use explicit `play()` to return to the RAM driver.

`pg.msm5205` exposes the same system source in other modes. The shorter global
`adpcm` is specific to PC Engine CD-ROM²; existing OPN/X68000 globals keep their
previous meaning. This step does not add a new generic `createSoundChip` type.

## Shared core and offline rendering

`native/msm5205/` contains the BSD-3-Clause C11 decoder, PCM host and PCE RAM
playback helper. Decoder/FIFO behavior is ported from Tetorica's existing,
licensed libvgm adaptation. Its author notices, references and distinctions are
in `LICENSE`, `NOTICE.md` and `README.md`. The Analyzer's existing JavaScript
renderer is retained; no VGM commands, gains or timing are changed.

Rebuild WASM with `sh scripts/build_msm5205_wasm.sh`. The fixed-memory core
allocates no objects, loads no files, and never calls the UI while rendering.
Native borrows immutable encoded RAM and releases its last owner off the audio
thread. Native allows 64 KiB each for current/retained RAM and a pending upload,
within a combined 128 KiB budget. Source and license snapshots are bundled for
standalone application builds; the fixed sound-chip SDK version is unchanged.

`createMSM5205PCM` from `web/msm5205_pcm.js` accepts `sampleRate` and `wasmBinary`
(or an asset URL). It offers synchronous `prepare`, `play`, `stop`, `reset`,
`writeRegister`, `render(left,right,frames)` and state/mix controls. Low-level raw
initialization deliberately preserves the legacy decoder's -2 DC predictor;
call `stop()` for an unloaded, strictly silent RAM driver. The Playground hosts
do this automatically. Stop/reset do not alter gain or mute.

For offline WAV output, borrow it alongside HuC6280 in
[`createCddaOffline({sources})`](cdda.md#offline-output). Wrap `render` in a
synchronous `processFrames(count)` returning planar Float32 arrays at the same
output rate. Use `offline.schedule(frame, callback)` for ADPCM/PSG controls;
CD-DA and both borrowed engines then advance through identical frame counts.
The actual-core three-source test is `web/msm5205_offline.test.mjs`.

This implements the audio paths, not the console CPU, DMA, interrupt controller,
SCSI/CD commands, BIOS or disc images. CD-DA still accepts only 44.1 kHz stereo
PCM16 WAV and track manifests. A VGM without external CD-DA audio and its timeline
cannot reconstruct CD tracks.
