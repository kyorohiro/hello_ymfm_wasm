# YM21280 OPS / YM21290 EGS

## CPU書き込み

以下の番地はDX7 CPU側。OP番号は人向けに1..6、バス上のオフセットは `s = 6 - OP`、発音枠は `v = CH - 1`。ROMラベルは[注釈付きv1.8逆アセンブル](https://github.com/ajxs/yamaha_dx7_rom_disassembly/blob/b9df0c0d2500a654904ff5e9bde1276e50fe010e/yamaha_dx7_rom_v1.8.asm)に対応する。

| アドレス | ROMまたはダイ解析で確認できること | 今回のモデル |
|---|---|---|
| 2804, 2805 | PATCH_ACTIVATE_ALG_MODE は30h/50h（キー同期有／無）の後に (algorithm << 3) + feedback を書く | 通常は全声に反映。ダイ解析に基づく個別Aレジスタ選択も実装。テストモードとシフト待ち時間は未実装 |
| 3000 + 2v | VOICE_ADD_LOAD_FREQ_TO_EGS は上位→下位の順に書く。14bit log pitch、左詰めで1oct = 1000h | MIDI A4を5AA8hで440 Hzとする近似。二度のバイト書き込みはレンダー境界で反映 |
| 3020 + 2s | PATCH_ACTIVATE_OPERATOR_PITCH。ratio/fixedをbit 0で選択。ratio 1の基準232Ch、fixed 1 Hzの基準16ACh | log2による位相増分。実機の整数テーブル・丸めの差が残る |
| 3030 + s | PATCH_ACTIVATE_OPERATOR_DETUNE。符号と3bitの大きさ | 符号付きcentの近似。音域別実測は未実施 |
| 3040 / 3060 + 4s + stage | PATCH_ACTIVATE_OPERATOR_EG_RATE / EG_LEVEL。4区間、rateは編集値×164の上位バイト。levelはROMの対数テーブル経由 | rateとlevelのCPU変換を実装。levelはTABLE_LOGの値を1ビット右シフトする。EGS側のゲイン曲線・消音点と到達時間は近似。離鍵で第4区間に進む |
| 3080 + 16s + v | VOICE_ADD_LOAD_OPERATOR_DATA_TO_EGS。96バイト。KLSとvelocityをCPUで合成する。FFhは消音 | OP別・CH別。MIDI入力、velocity感度と基本音量の変換はv1.8命令列に準拠。鍵盤曲線をROMの整数変換で計算。バイトからゲインへの変換は近似 |
| 30E0 + s | PATCH_ACTIVATE_OPERATOR_KBD_SCALING_RATE。AMS << 3 とrate scalingを合成 | 音域によるEG速度と振幅変調感度を近似 |
| 30F0, 30F2/3 | ファームウェアが計算した振幅変調と符号付きピッチ変調。ベンドを合算して上下バイトを書き込む | CPU側LFOの6波形・delay・sync、AM/PM書き込み、MIDIベンド加算に対応。各声のピッチEGは3000–301Fへ反映 |
| 30F1 | VOICE_RESET_EGS。bits 2..5は声番号、下位値1がon、2がoff | エッジとして扱う。同じ値の再書き込みもイベント |

## 確度と検証の限界

DX7の通常の音色変更は全声へ同じAlgorithm/Feedbackを書き込む。一方、OPSのダイには16個の設定を保持するシフトレジスタがあり、個別設定経路も報告されている。個別設定を実装した根拠は回路解析であり、著者自身も実機未試験としている。[Ken ShirriffのOPS制御レジスタ解析](https://www.righto.com/2022/02/yamaha-dx7-chip-reverse-engineering_7.html)

VOICE_ADD_POLYの空き声探索は巡回して最大16枠を調べ、全枠がactiveならこのルーチンから戻る。今回のAUTOはこの探索部分を実装した。MIDI受信バッファとモノ動作は未再現。

PCMはホストのサンプルレートで浮動小数点合成する。96スロットのクロック位相、log-sine ROM、DAC、EGS内部のラッチ遅延は未再現。A4周波数とレジスタ再演の一致はソフトウェアテストによる。実機の全パラメータや音色の一致は未確認。

## 単一キャリアの包絡比較（2026-11-25）

`node scripts/compare_fm21290_envelope.mjs` で同梱MSFAと独自コアを48 kHzで比較する。単一キャリアのA4、velocity 127、3秒押鍵と3秒離鍵、音色のR1/R4を同じ値に固定。L1..L4は99/80/80/0（EGSバイト0/9/9/63）、R2/R3は85（EGSバイト54）。5 msごとのPCMピークを測定した。

| R1/R4編集値（EGS値） | ピークの90%到達 ms（独自 / MSFA） | 定常振幅 dB・ピーク比（独自 / MSFA） | 離鍵後−20 dB到達 ms（独自 / MSFA） |
|---|---:|---:|---:|
| 40（25） | 315 / 310 | −13.5 / −13.5 | 990 / 1000 |
| 60（38） | 30 / 30 | −13.3 / −13.2 | 105 / 105 |
| 80（51） | 0 / 0 | −13.2 / −13.4 | 15 / 15 |

時刻は閾値を通過した窓の開始時刻。0 msは最初の5 ms窓を表す。修正前はR40で離鍵後−20 dBまで160 msだった。下降区間を対数ゲイン上の一定速度にし、立ち上がりの近似速度も調整した。MSFA内部のレート刻みは同梱の `third_party/tetorica-soundchip-native/vendor/msfa/env.cc` を参照した。低い音量からの再打鍵、音域別のrate scaling、曲線全体と実機との一致は未検証。

## 音域と出力レベルを変えた包絡比較

上記スクリプトは同じ48 kHz、R1/R4=40の条件で、OP1のRate Scalingを5にして測定する。レジスタの音高から3半音ごとにグループを求め、実効レートに加算して63で飽和させる。これは同梱MSFAの `dx7note.cc` のScaleRateを参照した比較モデル。ピッチベンドによる再計算では音域グループを変えない。

| 音高 | 出力レベル | ピークの90%到達 ms（独自 / MSFA） | 離鍵後−20 dB到達 ms（独自 / MSFA） |
|---|---:|---:|---:|
| A2 | 65 | 125 / 65 | 415 / 400 |
| A2 | 85 | 125 / 125 | 415 / 410 |
| A4 | 65 | 55 / 25 | 180 / 190 |
| A4 | 85 | 55 / 55 | 180 / 180 |
| A6 | 65 | 20 / 10 | 80 / 80 |
| A6 | 85 | 20 / 20 | 80 / 80 |

定常振幅のピーク比は6条件すべてで差0.2 dB以内。絶対ピークの差は4.2〜5.5 dBあり、出力レベルを下げた場合にMSFAのアタック到達が早くなる挙動も残る。単純なマスターゲインの調整で両方を合わせることはできない。

物理CH1のA4を3秒保持し、離鍵100 ms後に同じCH・同音を再発音すると、先頭5 msのPCMピークは初回−71.5 dBFS、再発音−49.0 dBFSだった。これは実験コアが残存包絡から立ち上がることの回帰試験。MSFAの公開APIは物理CHを指定できず、この結果の実機照合も未実施。

## MIDIベロシティとOP出力の再測定

v1.8のMIDI受信ルーチンは `velocity >> 2` をTABLE_MIDI_VELで打鍵時間に変換する。VOICE_ADD_LOAD_OPERATOR_DATA_TO_EGSはこの時間をさらに4で割り、TABLE_OP_VOLUME_VELOCITY_SCALEを参照する。感度をS、後者の表の値をVとすると追加の減衰は `15 − 2S + floor(V × S / 8)`。鍵盤スケーリング深度0では、基本減衰 `2 × TABLE_LOG[outputLevel]` との和を4..255に収めた値が出力バッファに書かれる。velocity 0は離鍵。非ゼロ深度の変換は下記の鍵盤スケーリングに従う。

バイトからPCMへの変換は比較モデル。以前のOL99・感度0のミックス音量を保つよう基準を合わせた。アタックの上昇速度は固定した減衰バイト43（OL85）と83（OL65）のPCM比較から推定し、暗騒音付近への外挿には上限を設けた。これは実機回路の同定結果ではない。

前節のOL65、Rate Scaling 5で90%到達はA2/A4/A6順に65/25/10 msとなり、MSFAと同じ5 ms窓に入った。別条件としてA4、OL85、感度4、Rate Scaling 0、R1/R4=40を固定してベロシティだけを変えた結果を示す。

| MIDI velocity | EGS OP出力バイト | アタック90% ms（独自 / MSFA） | ピーク dBFS（独自 / MSFA） | リリース−20 dB ms（独自 / MSFA） |
|---:|---:|---:|---:|---:|
| 32 | 82 | 160 / 160 | −48.7 / −42.2 | 990 / 1020 |
| 64 | 61 | 230 / 235 | −40.8 / −34.8 | 990 / 1015 |
| 96 | 45 | 305 / 305 | −34.7 / −29.1 | 990 / 995 |
| 127 | 35 | 360 / 360 | −31.0 / −25.7 | 990 / 1000 |

絶対音量はこの4条件で5.3〜6.5 dB低い。実機のDACゲインや測定系は未校正。比較スクリプトは既存の9条件と上記4条件について閾値到達時間と相対サステインを検証する。

## 鍵盤スケーリングの折点と曲線

v1.8のPATCH_ACTIVATE_OPERATOR_KBD_SCALING_LEVELはOPごとに43バイトの曲線を準備する。ノート発音時には移調済みキーコードの上位バイトを4で割ってスロットを選ぶ。曲線の生成ループは43から1へ数え、各結果を1つ前のスロットに置く。このため距離は「スロット + 1 − 折点グループ」。折点グループは編集値に20を加えてキーコード表を引き、その上位バイトを4で割った値である。

深さは `floor(depth × 660 / 256)` に量子化する。左右の線形／指数表から距離に対応する重みを読み、重みと量子化した深さの積の上位バイトを127で制限する。負曲線は減衰を加算し、正曲線は減算する。基本減衰との和を0..127に収めて2倍した後にvelocity補正を加える。

ROMの2つの曲線表は各36バイト。極端な折点と音高では表の末尾を越えて隣接する表を読む。実装はv1.8の表配置に従う。VOICE_ADDの移調も8bit減算後に符号なしで127に制限するため、例えばMIDI 0を1半音下げると127のキーコードになる。いずれも対象ROMの命令列からの結果で、実機のバストレースは未取得。

折点100値 × 左右カーブ16組 × 左右深さ3組（0/0、99/99、32/71）× MIDI 128鍵を比較した。OL65、velocity 127、感度0のOP1の出力レジスタ614,400バイトが、逆アセンブルから表を読み43スロットを構築した独立計算と一致した。通常の回帰試験には折点周辺、符号、中心から遠い両端、移調の境界を収録している。

## 制御CPUのLFO

v1.8のHANDLER_OCFはカウンタを0に戻し、比較値3140を設定する。LFO_GET_AMPLITUDE → MOD_AMP_LOAD_TO_EGS → MOD_PITCH_LOAD_TO_EGSの順に処理する。独自音源では音声スレッドでサンプル数から次の割り込み境界を求める。公称CPUタイマークロック1,178,312.5 Hzを用いた周期モデルで約375.26回/秒。割り込み入口の遅延・MIDI処理負荷・個々の命令に要する時間は含めていない。チップ単体のオフラインAPIは受け取った書き込みだけを処理する。

16bit位相増分はPATCH_ACTIVATE_SCALE_LFO_SPEED準拠。Speed 0/40/99での計算周波数は約0.0630 / 6.4876 / 49.6444 Hz。Triangle・Saw Down・Saw Up・Square・Sine・Sample & Holdはv1.8の分岐を用いる。Sineは折り返した64要素の表を参照し、S&Hは正から負への符号境界で8bit状態を更新する（乗数179、加数0x11）。S&Hの起動時の種は0と仮定した。Sync付きの新しい押鍵で共通位相を7FFFhに戻す。非ゼロDelayは押鍵時に待ち時間とフェードをリセットする。

音色のAMDとフェードから30F0hを、PMD・PMS・符号付き波形・MIDIベンドから30F2h/30F3hを生成する。両方が有効なtickではAM→PM上位→PM下位の順。無効な変調先への反復ゼロ書き込みは省略し、生レジスタ演奏を可能にする。無効化時は該当出力を解除する。画面のRegister writesに表示するAM/PMの3バイトは音声スレッドの実値。モジュレーションホイール、アフタータッチなどの追加ソースは今後の対象。

検証は `node --test docs/synth-fm21290/modulation.test.mjs`。44.1 kHzを37フレーム単位、48 kHzを128フレーム単位で1秒ずつレンダーし、375回のtickそれぞれで発生するAM/PMの書き込み時刻（最初の該当サンプル）、順序と値列を照合。単一キャリアのPCMでもAMによるレベル変化とPMによる音高変化を独立に検証した。比較の基準は命令列とモデルの公称周期で、実機計測は未実施。

## 各声のピッチEG

DX7 v1.8の `PATCH_ACTIVATE_PITCH_EG_VALUES` は音色のR1〜R4とL1〜L4をそれぞれ100項目の表で変換する。`PITCH_EG_PROCESS` はレベルを7ビット左シフトして保持する。押鍵でL4から順にL1、L2、L3へ移動し、L3を保持する。離鍵すると現在値からL4へ移る。各段の終了は増減後の上位バイトで判定し、終了時には下位バイトも含めて目標値に揃える。段階・現在値は物理16声で独立する。

`HANDLER_OCF` では `PORTA_PROCESS` が交互に8声分のピッチを書いた後、割り込み2回につき1回、全声のEGを進める。モデルは同じ更新順を使う。基準音高は既存のA4校正値を使用し、L50を基準に差分を加算する。ROMのマスターチューンとポルタメント、MIDI受信中の割り込み処理省略は未再現。アプリでは変化のないワードの再書き込みを省略し、押鍵時にはL4を即時反映する。実機での初回書き込み時刻と絶対音高は未測定。

## ポリモードの同音とサステイン

v1.8の `VOICE_REMOVE` はCH1から順に探し、指定ノートに一致した最初のactive声だけを処理して戻る。同音を二度押すと二つの枠を使い、巡回が一周した場合は後から押した低番号の枠が先に離鍵される。

ペダルを踏んで離鍵すると、制御CPUはその枠のactiveビットを落とし、sustainビットを立てる。EGSへのKey OffとピッチEGのリリースは保留する。`VOICE_ADD_POLY` はactiveビットで空きを判定するため、持続中の枠も再利用できる。再利用時は古いゲートを切り、新しいノートのactiveフラグで上書きする。ペダルを戻すと `MAIN_PROCESS_SUSTAIN_PEDAL` がsustainの残る枠にだけCH順でKey Offを送り、ピッチEGをリリースへ進める。

`_CONTROL_CHANGE_MESSAGE_PROCESS` は7ビットのCC値を左シフトし、`MIDI_RX_CC_64_SUSTAIN` はその値がゼロかを調べる。独自コアのSMF再生ではCC64の1〜127をオン、0をオフとした。MSFA再生は従来の64以上でオンとする処理を使う。検証対象はポリモードのゲート列。実機の音声測定と、鍵盤・外部MIDI双方が競合した際のMIDI受信バッファの再現は今後の対象。

## OPSの変調量と倍音

`node scripts/compare_fm21290_spectrum.mjs` は、同じ音色を独自コアと同梱MSFA WASMで演奏する。48 kHz、A4、velocity 127、feedback 0、EGのL1〜L3は99。発音後250〜500 msにHann窓を掛け、第1〜8倍音の振幅を各音の基本波に対するdBで表示する。

**実装の根拠**。MSFAの `Env::target` と `Dx7Note::compute` の換算では、OL99、感度0、EGレベル99の定常出力は位相2周期分になる。独自コアでは同条件の出力レジスタ値が15、振幅が `2^(-4/16)`。この振幅で位相偏移が4πラジアンになるよう、OP間バスの係数を変更した。これはMSFAに基づく換算で、OPS実機の固定小数点形式は未確定。

| 条件 | PCMで確認した結果 |
|---|---|
| Algorithm 32、単一キャリア／同周波数の並列2キャリア | 第2〜8倍音は両エンジンとも基本波比 −96 dB以下 |
| Algorithm 1、OP2 → OP1、比1:1、OP2のOL75 | 第2倍音は旧モデル −5.5 dB、変更後 +9.1 dB、MSFA +8.9 dB |
| Algorithm 31、OP6 → OP5、比2:1、OP6のOL75 | 第3倍音は −10.3／−10.9 dB（独自／MSFA）。第2・4・6・8倍音は両方とも −95 dB以下 |
| 6OP、全32アルゴリズム、OP1→6のレベル77/69/64/74/66/61、周波数比1/2/1/4/2/1 | 出力経路の応答差を補正した後、比較対象の倍音の最大差は0.13 dB |

MSFAには出力フィルタとリサンプラがある。比較スクリプトでは比1〜8の単一キャリアを別に測定し、両エンジンの出力経路の周波数応答差を差し引く。ログの両スペクトルは未補正値。MSFAで −70 dB以上の成分には補正後の差を判定し、それより弱い成分は両者とも −65 dB未満かを確認する。この検証は定常音に限定しており、フィードバック、キーオン直後の位相、実機DAC出力は未照合。[同梱MSFAの出力経路](../js/msfa_dx7/README.md)
